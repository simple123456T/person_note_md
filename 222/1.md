# 面试题库 100 题 · 参考答案（一）：结构篇 + 训练篇

> 每条是面试口径的"要点"。答出大部分要点即算过；能展开举例、给出数字更好。

## 结构篇（1–28）

**1.** Attention(Q,K,V) = softmax(QKᵀ/√d)·V。QKᵀ 是 n×n 矩阵（每对 token 交互一次），再乘 d 维 V → 计算与显存都是 O(n²·d)。

**2.** 点积方差随 d_k 线性增大，不缩放则 logits 过大 → softmax 饱和接近 one-hot → 梯度趋零、训练不稳。√d_k 把方差归一到 ~1。

**3.** 不同头在不同子空间学不同关系模式（句法/指代/位置），等价于集成，增强表达。不是越多越好：收益递减、KV cache 与计算线性变贵、单头维度变窄可能欠拟合；常用 8~32 头。

**4.** BN 沿 batch 维统计：变长序列统计不稳、自回归推理时没有 batch 概念、小 batch 失效。LN 对每个 token 的特征维归一化，与 batch 无关，天然适配序列。

**5.** 提供恒等捷径：缓解深层梯度消失，让"深堆层"可行；信息可跨层直通，坏层不易毁掉整条链路。

**6.** self-attention 对输入排列等变（打乱 token 输出跟着乱），必须显式注入顺序；去掉则"猫咬狗"和"狗咬猫"对模型等价。

**7.** 参数量：两个矩阵 (d→4d→d) 约 8d²，占每层 ~2/3 参数；功能：逐位置非线性变换，被认为是"知识/事实记忆"的主要存储层。

**8.** BERT（Encoder-only）：分类、NER、检索等理解任务；T5/BART（Enc-Dec）：翻译、摘要等输入输出异构任务；GPT/Qwen/LLaMA（Decoder-only）：生成与通用任务。

**9.** causal mask：上三角置 -inf，防当前位置看到未来（训练并行 + 生成合法）；padding mask：屏蔽 pad token 防止污染注意力。实现：causal 是固定下三角矩阵；padding 按每个序列实际长度生成，两者叠加使用。

**10.** x[d_model] → LN → QKV 投影（d→d 或 GQA 后 kv 更小）→ attention（输出 d）→ 残差 → LN → FFN（d→4d→d，SwiGLU 则 8/3·d）→ 残差。核心：block 前后 d_model 不变，FFN 中间层先放大再压回。

**11.** Post-Norm：x + Norm(Sub(x))，每层输出都被归一化，深层梯度经过 norm 雅可比衰减、难训；Pre-Norm：x + Sub(Norm(x))，存在不衰减的恒等捷径，深层稳定。Post 理论上限略高但需要精细 warmup；现代 LLM 几乎全用 Pre。

**12.** RMSNorm 去掉均值中心化，只用均方根缩放（少一步、少一遍扫描）；效果与 LN 基本一致、更快，成为主流（LLaMA/Qwen）。

**13.** 对位置 m 的 Q/K 左乘正交旋转矩阵 R(mθ)（分维度不同频率）。正交性保证 ⟨R_m q, R_n k⟩ = ⟨q, R_{n−m} k⟩ → 内积只依赖相对位置 m−n，且不衰减。

**14.** ALiBi：注意力分数直接加 −slope·|m−n| 的线性距离惩罚，免训练、外推简单有效；缺点是"远处必衰减"的硬约束、灵活性不如 RoPE。RoPE + 插值类方案是当前主流。

**15.** 缓存历史 token 的 K/V，每步只算新 token 的 q 并复用历史 → 每步注意力从重算 O(n²) 变为增量 O(n)。显存 = 2 × n_layers × kv_heads × head_dim × seq_len × batch × dtype_bytes（2 = K 和 V）。

**16.** MQA：所有 Q 头共享 1 组 KV（cache 最省、质量有损）；GQA：分组共享（如 32 Q 头 / 8 KV 组）。GQA 质量损失极小而 cache 缩小数倍，是质量-显存的折中，故成主流。

**17.** FFN 改为 SwiGLU(x) = (SiLU(xW₁) ⊙ xW₃)W₂（门控分支）。门控 + 平滑激活的梯度性质更好，同计算量效果优于 GELU-FFN；代价是三个矩阵，需把隐层缩到 8/3·d 保持参数量。

**18.** PI：位置 id 线性缩放（等效把长序列"压"回训练长度）；NTK-aware：改 RoPE 基频，高频少插值低频多插值；YaRN：NTK 改进 + 注意力温度修正，对短序列性能损伤更小，是目前常用方案。

**19.** decoder-only 每个位置的 token 都有 next-token 监督（n 个 token 贡献 n 个 loss），监督信号密度最高；且一个目标统一了几乎所有 NLP 任务，数据利用效率最高。

**20.** tied：省 d_model×vocab 的参数（小模型显著）、输入输出分布一致；untied：输出头有独立容量，大模型/大词表下效果更好。小模型常 tied，大模型常 untied。

**21.** 三条路线：①改复杂度：稀疏注意力、滑窗、线性注意力；②IO/系统优化：FlashAttention（不改复杂度，减 HBM 读写）；③KV 压缩：GQA/MLA、KV 量化。FlashAttention 属于第②类。

**22.** 大词表：编码更短（推理快）、无 OOV、多语言友好，但 embedding/输出层参数大、低频 token 学不透、softmax 变贵；小词表反之。常见 32k~256k，按语料和任务权衡。

**23.** 要点：把 Q/K 每 2 维视为复数/二维点，第 i 组频率 θᵢ = base^(−2i/d)；位置 m 的向量旋转 m·θᵢ 角。由正交旋转保内积：⟨R_m q, R_n k⟩ = ⟨q, R_{n−m} k⟩，得相对位置依赖；再说明幅值不衰减、可逆（与绝对位置编码信息等价）。

**24.** 维护 running max m、running 和 ℓ、累加输出 acc；读入新块算局部 max，用 exp(m_old − m_new) 修正历史项后合并。证明：所有项的指数底一致化后与一次性 softmax 逐项相等（数值稳定性也更好）。

**25.** MLA 把 K/V 压缩成低维 latent 向量 c_kv（如 512 维），注意力时再上投影；上投影矩阵可吸收进 Q/K/V 变换中，因此 KV cache 只需存 latent（外加为兼容 RoPE 解耦出的一小段 key），cache 体积比 MHA 小一个量级。

**26.** 每个 MoE 层有 N 个 expert，router 对每个 token 做 softmax 选 top-1/2 个 expert，只计算被选中的 → 总参数大、单 token 计算量不变。负载不均衡会让部分 expert 过载：加 auxiliary load-balancing loss 惩罚路由偏斜（+路由噪声、z-loss 等手段）。

**27.** Michel et al.《Are Sixteen Heads Really Better than One?》：训练后多数层的大量头可剪除且几乎无损。启示：注意力头存在大量冗余，推理可做头剪枝/结构化压缩省钱；也说明"多头多样性"主要在训练期起作用。

**28.** 注意力负责 token 间"信息路由"，计算贵但参数少；FFN 是逐位置的知识存储（key-value memory），scaling 实验显示模型能力与知识容量强相关 → 参数预算更多给 FFN 收益更高。近似 2:1（注意力 4d² vs FFN 8d²）。

## 训练篇（29–60）

**29.** 预训练：海量无标注文本，next-token prediction，学语言能力 + 世界知识（TB 级，要"干净"）；SFT：指令-回答对（万~百万级），学对话格式与指令跟随；RLHF/DPO：偏好对（chosen/rejected，千~十万级），对齐有用性、安全性、风格。

**30.** 预训练：logits 与 label 错开一位（token i 预测 i+1），全序列都算 loss。SFT：prompt 部分 mask 掉，只对 assistant 回答算 loss——否则模型把容量浪费在"学复述问题"上，且 loss 被长 prompt 稀释。

**31.** 初期参数随机、梯度大且方向噪声大，直接大学习率易震荡/发散；warmup 小步走出最不稳定区。没有 warmup 的典型现象：开局 loss 降不动甚至 spike。

**32.** 微调后预训练获得的通用能力明显下降。缓解：混入一定比例通用数据、更低学习率、LoRA 限制权重改动幅度、早停。

**33.** 训练角度：重复样本浪费算力、加剧记忆化；评测角度：训练集与 benchmark 重合会让分数虚高、失去参考意义。

**34.** 按全局梯度范数裁剪（clip 到 1.0 是常见值），防个别坏 batch 的大梯度把参数打飞；配合 grad norm 监控。

**35.** 常见 1~4 epoch。重复数据边际收益递减，且增加记忆化/过拟合风险（数据重复 scaling 的研究结论：少量重复无妨、多轮重复价值骤降）。

**36.** 评测集内容混进训练数据 → 分数虚高。防：训练语料对主流 benchmark 做去重、评测集不外泄、发布前做污染审查（n-gram / embedding 重叠检测）。

**37.** 训练：从字符级词表开始 → 统计语料中相邻 pair 频率 → 合并最高频 pair 成新词 → 重复直到达到目标词表。编码：按学到的合并规则（优先级）对文本贪心切分。能现场模拟"low→lower"式两三步合并最好。

**38.** AdamW 把 weight decay 从梯度一阶/二阶矩的自适应缩放中解耦出来（直接作用在参数上）；L2 正则是加进 loss、会被自适应缩放稀释。二者不等价，AdamW 是 LLM 事实标准。

**39.** 平滑无阶梯、后期小步长精细收敛、对 warmup 适配好；最终学习率（eta_min）常设峰值的 ~10%（0.1×peak），太早衰减到 0 会浪费尾部训练。

**40.** 数值上基本等价（loss 按 token 归一时）；差别：dropout 随机性不同步、通信/优化器更新次数不同（累积省通信）。工程动机：单卡显存放不下目标 batch，用"小 batch × 累积步数"等效。

**41.** FP16：尾数多但动态范围小，小梯度会下溢 → 需 loss scaling（放大 loss 保住小梯度，反传后除回去）；BF16：指数位与 FP32 相同、范围大、基本免 scaling，尾数少精度略低。现代 LLM 默认 BF16。加速来自 Tensor Core + 显存带宽减半。

**42.** 前向只存分段检查点、反向时重算段内激活：激活显存从 O(n) 降到 O(√n)（或更低），代价是多一次前向计算（时间 +20~35%）。

**43.** 1B 参数：权重 BF16 2 GB + 梯度 2 GB + Adam 状态 m/v（FP32）8 GB +（主权重 FP32 4 GB，视实现）≈ 12~16 GB，另加激活值（随 batch×seq 增长，可用 checkpointing 压缩）。答出"参数:梯度:优化器 ≈ 2:2:8（每 1B）"这个比例最关键。

**44.** LoRA 只训增量 BA：梯度/优化器状态只剩增量参数（通常 <1%），底座冻结只读（1B ≈ 2 GB）+ 激活 → 几 GB 显存可调几 B 模型；全参按 43 题口径要大一个数量级。

**45.** 原因：脏数据/坏 batch、数据分布突变（换数据源）、学习率过大、数值溢出（FP16）、超长样本突现。流程：记录 spike 前后 batch → 回滚最近 checkpoint → 跳过嫌疑数据 + 梯度裁剪 → 盯 grad norm 和 embedding/lm_head 等敏感层 → 重启续训。

**46.** ZeRO-1：切优化器状态；ZeRO-2：再切梯度；ZeRO-3：再切参数（前向时临时 all-gather）。显存收益递增、通信量递增（3 的通信代价明显）。

**47.** DP 切数据、TP 切层内权重矩阵、PP 切层、EP 切 expert。中小模型 ZeRO-DP 足够；大模型典型组合：TP（层内）+ PP（层间）+ DP（数据），MoE 加 EP。能说出"TP 通信频繁所以限制在机内 NVLink，PP 跨机"更好。

**48.** DPO：偏好对上直接优化闭式目标，隐式 reward = β·log(π/π_ref)，省掉 RM 训练 + 在线采样 + critic；优点：稳定、实现简单、离线数据即可。缺点：静态数据易过拟合偏好格式、探索性弱。PPO：在线采样上限高但工程重、超参敏感、训练不稳。

**49.** 流程：SFT 初始化 → 采样并人工标注偏好 → 训练 reward model → PPO 优化策略（reward + KL 惩罚防跑飞）→ 迭代。reward hacking：策略找到 RM 的漏洞刷分（冗长、谄媚、固定格式）而非真正变好——RM 是真实偏好的有损代理。

**50.** LIMA（1000 条精选数据 SFT 出强模型）的核心结论：质量 > 数量，"少而精"即可激发预训练能力。实践口径：清洗严格、多样性足、难度分层，比堆量重要；量太少则覆盖不足，两者要平衡。

**51.** 按目标能力定 domain 权重（网页/代码/数学/多语言/书籍…），用小规模 scaling 实验外推配比；训练中按各域 loss 与评测反馈调整；高风险高价值域（代码/数学）上采样但防过拟合；阶段化切换（退火阶段换高质量数据）。

**52.** MFU = 实际达到的模型 FLOPs/s ÷ 硬件理论峰值 FLOPs/s。训练健康值约 35~55%（受并行策略、框架、模型形状影响）；它是横向比较训练效率、发现配置问题的核心指标。

**53.** 模型权重 + 优化器状态（m/v）+ LR 调度器进度 + dataloader 消费位置 + RNG 状态 + 全局步数/指标。只存权重无法严格续训（优化器动量和数据进度丢失，会重现 warmup/重复数据）。

**54.** PPL 反映语言建模本身（训练健康度、数据适配），benchmark 反映下游能力（知识/推理/代码）。防泄漏：eval 集不进任何训练阶段、对训练语料去重 against eval、定期换卷、报告污染审查。

**55.** Chinchilla：给定算力预算，计算最优配置 ≈ 20 tokens/参数（数据与参数等比放大）。实际模型都 over-train（如 LLaMA 8B 用 15T token ≈ 1900:1）：推理成本是长期的、训练是一次性的 → 宁可小模型多喂 token 换低推理成本。

**56.** 关键步骤：KL 约束的 RLHF 最优解 π*(y|x) ∝ π_ref(y|x)·exp(r(x,y)/β) → 反解 r = β·log(π*(y|x)/π_ref(y|x)) + β·log Z(x) → 代入 Bradley-Terry 偏好概率（配分函数 Z(x) 在正负样本差中消掉）→ 得到 DPO 损失：−log σ(β·[log π(y_w)/π_ref(y_w) − log π(y_l)/π_ref(y_l)])。

**57.** GRPO（DeepSeek）：每个 prompt 采样一组 G 个输出，用组内 reward 归一化（减均值除标准差）当 advantage → 完全砍掉 critic 价值网络。可行原因：同 prompt 组内对比天然提供基线，省显存省工程，R1 式可验证奖励（数学/代码）下效果很好。

**58.** 要点：数据——长文档上采样 + 合成数据、控制长度分布；RoPE——调大基频（如 1e4→1e6）或用 PI/YaRN；工程——FlashAttention 必须 + 序列并行 + checkpointing 控激活显存；策略——分阶段渐进加长（先 4k 稳定再加 32k）。

**59.** 常见故障：节点/卡坏（自动摘除 + 快速从 checkpoint 重启 + 热备容量）、straggler 慢节点（定位慢盘/慢链路）、NaN/数值不稳（跳批、查 FP16 溢出、降 LR）、存储吞吐跟不上（数据加载瓶颈）、调度抢占。对策核心：密集 checkpoint + 自动容错 + 监控 grad norm/MFU。

**60.** annealing/mid-training：训练尾段切换到最高质量数据（含领域数据、长文本、代码/推理数据），常配合降 LR。原因：尾段学习率小、参数只做精细调整，此时喂什么数据就"定调"什么能力，对下游分数影响显著。
