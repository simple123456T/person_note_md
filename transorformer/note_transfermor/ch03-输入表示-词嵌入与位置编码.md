# 第 3 章 输入表示：词嵌入与位置编码

> **本章目标**：搞清楚 Transformer 的输入到底长什么样，以及为什么必须有位置编码。
>
> 一句话预告：**Transformer 的输入 = 词嵌入 + 位置编码**。
> 两者的维度必须相同，因为要做**逐元素相加**。

---

## 3.1 从文字到数字：三级跳

计算机不认识"我"这个字，所以需要转换。Transformer 的转换分三步：

```
第 1 步：分词（Tokenization）
   "我有一只猫"  →  ["我", "有", "一只", "猫"]

第 2 步：查词表转 id
   ["我", "有", "一只", "猫"]  →  [1024, 3351, 882, 2213]
                                     ↑ 每个词在词表里的编号

第 3 步：查嵌入表转向量
   [1024, 3351, 882, 2213]  →  [[0.2, -0.5, ..., 0.8],     ← 512 个数
                                 [1.3,  0.1, ..., -0.2],    ← 512 个数
                                 [0.0,  0.7, ..., 0.4],
                                 [0.9, -0.3, ..., 0.1]]
                                 
   得到矩阵 X，形状 (4, 512)
```

### 关于分词，你需要知道的两件事

**1. 实际用的不是"字"或"词"，而是 subword（子词）**

中文一个字一个 token 还好，英文如果按单词分，"running"、"runs"、"ran" 会被当成三个毫不相干的词，词表会爆炸（几十万上百万）。所以实际用 BPE、WordPiece 这类算法切成子词：

```
"unbelievable"  →  ["un", "believ", "able"]
"Transformer"   →  ["Trans", "former"]
```

常见词保持完整，罕见词拆成片段。词表大小通常 3 万 ~ 15 万。

**2. 原文里 bang 说"假设一个字为一个 token"，这是简化**

对理解原理没有任何影响。本文档统一按"一个 token 一行"来讲。

## 3.2 词嵌入（Word Embedding）

### 它是什么

**一张查询表**（lookup table），形状是 `(词表大小, d_model)`：

```
        维度0   维度1   ...  维度511
id=0    [0.1,  -0.2,   ...,  0.3]     ← <pad>
id=1    [0.4,   0.7,   ..., -0.1]     ← <bos>
...
id=1024 [0.2,  -0.5,   ...,  0.8]     ← "我"
...
id=3351 [1.3,   0.1,   ..., -0.2]     ← "有"
```

给一个 id，就取出对应那一行。**这张表里的数字是训练出来的参数**，跟网络其他权重一起学。

### 怎么得到这张表

两种路子，原文提了：

| 方式 | 说明 | 例子 |
|---|---|---|
| **预训练好再拿来用** | 用海量语料单独训练词向量，然后固定或微调 | Word2Vec、GloVe、fastText |
| **端到端训练** | 和 Transformer 一起从零学，让词向量服务于当前任务 | 现代大模型全用这个 |

**现代大模型（BERT、GPT）基本都用第二种** —— 因为预训练词向量是"上下文无关"的（"bank" 永远同一个向量），而端到端学出来的词向量能配合上下文机制，效果更好。而且现在数据量足够大，自己学完全学得动。

### 为什么嵌入能表达语义

训练好的词向量有个神奇性质：**语义相近的词，向量也相近**。

```
   cos(国王, 女王) ≈ cos(男人, 女人)
   
   甚至能做算术：
   vec("国王") - vec("男人") + vec("女人") ≈ vec("女王")
```

直观理解：512 个维度里，某些维度可能编码"性别"，某些编码"年龄"，某些编码"是否生物"……不过实际上每个维度没有这么清晰的语义，是分布式编码的。

### 一个细节：乘 $\sqrt{d_{model}}$

论文里嵌入向量要乘上 $\sqrt{d_{model}}$：

```python
return self.lut(x) * math.sqrt(self.d_model)
```

**为什么？** 因为位置编码的值域是 $[-1, 1]$，而随机初始化的词嵌入数值很小（标准差约 $1/\sqrt{d}$）。如果不放大词嵌入，**位置信息会淹没词义信息**。乘上 $\sqrt{d}$ 让两者量级接近。

> 这一条不是理论必然，是个工程经验。后来的实现（配合 LayerNorm、更好的初始化）里很多都不乘了，效果也没差多少。

## 3.3 位置编码：为什么必须有

### 问题：Self-Attention 是"无序"的

这是 Transformer 最反直觉的一点。看 Self-Attention 的核心运算：

$$Z = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

**这里没有任何一步包含"位置"信息。**

具体说：如果把输入矩阵的两行交换一下：

```
原输入:               交换后:
[ 我  ]               [ 猫  ]
[ 有  ]      →        [ 有  ]
[ 猫  ]               [ 我  ]

注意力输出会怎么变？
   输出矩阵的两行也对应交换了，但每一行的数值完全不变！
```

也就是说：**模型看到「我 有 猫」和「猫 有 我」，算出来的每个词向量是一模一样的**（只是顺序不同）。

这叫**置换等变性（permutation equivariance）**。用原文的话说：

> Transformer 本身是不能利用单词的顺序信息的，因此需要在输入中添加位置 Embedding，**否则 Transformer 就是一个词袋模型了**。

"词袋模型"就是：把所有词扔进一个袋子，不管顺序。显然「我打你」和「你打我」不能一样。

### 解决方案：往输入里"掺"位置信息

在词嵌入上**加上**一个只跟位置有关的向量：

$$x_i = \text{Embedding}(token_i) + PE_i$$

```
位置 0:  [0.2, -0.5, ..., 0.8]  +  [0, 1, 0, 1]         =  [0.2, 0.5, ..., 1.8]
         └── 词"我"的嵌入 ──┘       └─ 位置0 的 PE ─┘

位置 1:  [1.3,  0.1, ..., -0.2] +  [0.8415, 0.5403, ...] =  [2.14, 0.64, ...]
         └── 词"有"的嵌入 ──┘       └─ 位置1 的 PE ─┘
```

这样，**同一个词在不同位置，最终的输入向量就不同了**，模型就能区分顺序。

## 3.4 位置编码的公式

论文用的公式：

$$PE_{(pos,\,2i)} = \sin\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

$$PE_{(pos,\,2i+1)} = \cos\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

其中：

- $pos$：词在句子中的位置（0, 1, 2, ...）
- $d_{model}$：嵌入维度（512）
- $i$：维度编号（0, 1, ..., $d_{model}/2 - 1$）
- $2i$：偶数维度用 sin
- $2i+1$：奇数维度用 cos

### 用文字说人话

**偶数维用 sin，奇数维用 cos；不同维度用不同的频率。**

把 $10000^{2i/d}$ 记为 $\omega_i$（角频率），公式就是：

$$PE_{(pos)} = \left[\sin(\omega_0 \cdot pos),\ \cos(\omega_0 \cdot pos),\ \sin(\omega_1 \cdot pos),\ \cos(\omega_1 \cdot pos),\ \dots\right]$$

- $i=0$ 时，$\omega_0 = 10000^0 = 1$ → **变化最快**的波（周期 $2\pi \approx 6.28$）
- $i$ 增大，$\omega_i$ 变小 → 波长越来越长
- $i = d/2 - 1$ 时，$i=255$，$\omega_{255} = 10000^{-510/512} \approx 10000^{-1} = 10^{-4}$ → **变化极慢**

就像**一组频率不同的钟表指针**：有的转得飞快（编码细粒度位置），有的几乎不动（编码粗粒度位置）。这个设计借用了信号处理里的**正弦位置编码**思路。

### 手算示例（$d_{model}=4$，只看前 4 个位置）

$d=4$ 时只有两个频率：

- $i=0$：$\omega_0 = 10000^{0/4} = 1$
- $i=1$：$\omega_1 = 10000^{2/4} = 100$

| pos | 维度0<br>$\sin(pos)$ | 维度1<br>$\cos(pos)$ | 维度2<br>$\sin(pos/100)$ | 维度3<br>$\cos(pos/100)$ |
|---|---|---|---|---|
| 0 | 0.0000 | 1.0000 | 0.0000 | 1.0000 |
| 1 | 0.8415 | 0.5403 | 0.0100 | 0.9999 |
| 2 | 0.9093 | -0.4161 | 0.0200 | 0.9998 |
| 3 | 0.1411 | -0.9900 | 0.0300 | 0.9996 |

**观察**：

- 维度 0/1 变化很快：pos 从 0 到 1，值就从 (0, 1) 跳到 (0.84, 0.54)。
- 维度 2/3 变化很慢：pos 到 3 了，维度 3 还几乎是 1.0。
- 每一行的"模式"都是独一无二的 → 每个位置拿到一个独特的"指纹"。

> 这组数字可以用 `code/` 里的脚本复现，和我这里列的完全一致。

## 3.5 用 sin/cos 的两个好处

论文明确给了两条理由。

### 好处一：能外推到训练时没见过的长度

**如果**位置编码是可训练的参数（比如也做成一个 `(max_len, d)` 的嵌入表），那你就得预先定好 `max_len`。训练时最长见过 512，来了个 600 词的句子，第 600 个位置的编码**根本没训练过**，模型直接懵。

**用公式就没这个问题**：不管 $pos$ 是 600 还是 60000，$\sin$ 函数照样能算出值来，形式完全一致。

> bang 的原文表述：使 PE 能够适应比训练集里面所有句子更长的句子。

### 好处二：模型容易学到"相对位置"

**这是更本质的好处。**

固定一个距离 $k$，$PE(pos+k)$ 可以由 $PE(pos)$ **通过一个只跟 $k$ 有关的线性变换**得到。证明用两角和公式：

$$\sin(\omega(pos+k)) = \sin(\omega\, pos)\cos(\omega k) + \cos(\omega\, pos)\sin(\omega k)$$

$$\cos(\omega(pos+k)) = \cos(\omega\, pos)\cos(\omega k) - \sin(\omega\, pos)\sin(\omega k)$$

写成矩阵形式：

$$\begin{bmatrix} \sin(\omega(pos+k)) \\ \cos(\omega(pos+k)) \end{bmatrix} = \underbrace{\begin{bmatrix} \cos(\omega k) & \sin(\omega k) \\ -\sin(\omega k) & \cos(\omega k) \end{bmatrix}}_{\text{只和 } k \text{ 有关，是一个旋转矩阵}} \begin{bmatrix} \sin(\omega\, pos) \\ \cos(\omega\, pos) \end{bmatrix}$$

**这就是一个旋转矩阵**：位置增加 $k$，等价于在 (sin, cos) 组成的平面上**旋转一个固定角度**。

**实测验证**（$\omega=1$）：

| $k$ | 从 $PE(pos)$ 旋转得到 | 直接算 $PE(pos+k)$ | 是否一致 |
|---|---|---|---|
| $k=1,\ pos=0$ | (0.8415, 0.5403) | (0.8415, 0.5403) | ✅ |
| $k=1,\ pos=1$ | (0.9093, -0.4161) | (0.9093, -0.4161) | ✅ |
| $k=2,\ pos=0$ | (0.9093, -0.4161) | (0.9093, -0.4161) | ✅ |
| $k=2,\ pos=2$ | (-0.7568, -0.6536) | (-0.7568, -0.6536) | ✅ |

**为什么这很重要？**

因为语言里大多数规律是**相对位置**的，不是绝对位置：

```
"我 昨天 去 了 公园"
"他 前天 去 了 学校"

"去" 和 "了" 总是相邻（相对距离 1），
但它们的绝对位置（2 和 3，还是 2 和 3）会随句子变化。
```

模型真正需要学的是「距离为 1 的两个词有某种关系」，而不是「位置 2 和位置 3 有某种关系」。

因为 $PE(pos+k)$ 与 $PE(pos)$ 之间存在固定角度的线性关系，**注意力机制（本身全是线性变换 + 内积）就有能力直接学到这个相对关系**。这是 sin/cos 编码比"可学习绝对位置编码"更优雅的地方。

> **补充**：这条理论优势在现代大模型里被 RoPE（旋转位置编码）继承并发扬光大了 —— RoPE 直接把 Q/K 向量按位置旋转，让注意力分数天然只依赖相对距离。详见 [ch14](ch14-从Transformer到GPT.md)。

## 3.6 为什么是"相加"而不是"拼接"

一个非常高频的疑问。

**拼接**是把词嵌入和位置编码接成 1024 维：

$$[\text{embed}_{512};\ \text{PE}_{512}] \in \mathbb{R}^{1024}$$

**相加**是保持 512 维：

$$\text{embed}_{512} + \text{PE}_{512} \in \mathbb{R}^{512}$$

论文选了相加。理由：

**1. 维度不用翻倍，参数不用翻倍**

如果拼接，后面所有层的 $W^Q$、$W^K$ 等矩阵都要从 $512\times512$ 变成 $1024\times512$，参数直接翻倍。

**2. 两者信息其实能共存**

有人会想：相加不会把两种信息搅在一起分不开吗？

不会。因为高维空间有足够的"余量"。词嵌入和位置编码是两组**不同分布**的向量，模型后续的线性层可以把它们当成不同的方向来处理。用个粗糙的类比：

```
二维平面上：
  词义信息主要在"水平方向"变化（由训练决定）
  位置信息主要在"垂直方向"变化（由公式决定）

两者相加后落在不同象限，一个线性变换就能把
"水平分量"和"垂直分量"分别提取出来
```

**3. 实验上效果没差**

后续有大量实验对比过拼接、相加、甚至相乘，结论是**相加最简单且效果不差**。工程上自然选简单的。

**一个更有意思的视角**：相加可以看成是"把位置信息作为一个偏置项（bias）注入"。

## 3.7 位置编码的实现代码

```python
import torch
import torch.nn as nn
import math

class PositionalEncoding(nn.Module):
    def __init__(self, d_model, dropout=0.1, max_len=5000):
        super().__init__()
        self.dropout = nn.Dropout(p=dropout)

        # 预先把 (max_len, d_model) 的表格算好，注册成 buffer（不参与训练）
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(0, max_len, dtype=torch.float).unsqueeze(1)  # (max_len, 1)

        # 计算 10000^(2i/d_model)
        # 写成 exp(i * -log(10000) / d_model) 是为了数值稳定 + 向量化
        div_term = torch.exp(torch.arange(0, d_model, 2).float()
                             * (-math.log(10000.0) / d_model))

        pe[:, 0::2] = torch.sin(position * div_term)   # 偶数维
        pe[:, 1::2] = torch.cos(position * div_term)   # 奇数维
        pe = pe.unsqueeze(0)                            # (1, max_len, d_model)
        self.register_buffer('pe', pe)

    def forward(self, x):
        # x: (batch, seq_len, d_model)
        # 只取前 seq_len 个位置，靠广播自动加到每个样本上
        x = x + self.pe[:, :x.size(1)]
        return self.dropout(x)
```

**两个实现细节**：

1. **`torch.exp(...)` 而不是 `10000 ** (...)`**：$\exp$ 和 $\log$ 的写法数值更稳定，且支持向量化。

2. **`register_buffer`**：位置编码是固定的，不是要训练的参数。用 `register_buffer` 会把它存进 `state_dict`（方便保存/加载模型），但不会出现在 `model.parameters()` 里（不被优化器更新）。

## 3.8 后续发展：位置编码的演进

论文的 sin/cos 不是终点。简要了解（细节见 [ch14](ch14-从Transformer到GPT.md)）：

| 方案 | 提出 | 核心思想 | 用在哪 |
|---|---|---|---|
| **Sinusoidal** | 2017 原文 | sin/cos 固定公式 | 原版 Transformer |
| **Learned Absolute** | BERT (2018) | 可训练的嵌入表 | BERT、GPT-2 |
| **Relative PE** | Shaw et al. / T5 | 直接编码相对距离的桶 | T5 |
| **RoPE** | RoFormer (2021) | 把 Q/K 按位置**旋转**，注意力分数只看相对角度 | LLaMA、Qwen、几乎全部现代 LLM |
| **ALiBi** | 2021 | 不加位置编码，直接在注意力分数上按距离扣分 | BLOOM 等 |
| **NoPE** | 2023+ | 有些结构不加也行 | 研究阶段 |

**RoPE 特别值得提一句**，因为它和本章 3.5 的推导一脉相承：

> 既然 $PE(pos+k) = R_k \cdot PE(pos)$（旋转），那不如**直接对 Q、K 向量做旋转**。
> 这样 $q_i \cdot k_j$ 的结果天然只依赖于 $(i - j)$，**相对位置直接内建到了注意力计算里**。

## 3.9 本章小结

- Transformer 输入 = **词嵌入（学出来的语义）+ 位置编码（算出来的位置）**。
- 没有位置编码，Self-Attention 就是**词袋模型**，完全分不清语序。
- 位置编码公式：**偶数维 sin，奇数维 cos，不同维度不同频率**。
- 用 sin/cos 的两大好处：**能外推到更长序列**、**相对位置可表示为线性变换（旋转）**。
- 词嵌入与位置编码**逐元素相加**，不是拼接；相加更省参数，效果不差。
- 现代 LLM 普遍改用 **RoPE**，但思路是 sin/cos 那套"相对位置"思想的延续。
