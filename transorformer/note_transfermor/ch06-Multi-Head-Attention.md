# 第 6 章 多头注意力（Multi-Head Attention）

> **本章目标**：搞清楚"多头"到底是什么、为什么要切分、切分后怎么拼回来，
> 以及一个最常见的误解 —— 多头**不是**把句子分成几段。

---

## 6.1 为什么需要多头

### 一个头不够用

回想 [ch05](ch05-QKV深入理解.md) 5.7 节那张表：三个头算出来的注意力权重**完全不同**。

- head 0：「个」极度关注「我」（85%）
- head 1：「一」关注自己（61.7%）
- head 2：「我」关注自己（80.8%）

**如果只有一个头，模型只能学到一种"关注方式"。**

但语言里的关系是多维度的。看这个句子：

```
  小明     把     苹果     给     了     小红
   ↑                ↑                ↑
 主语            宾语             间接宾语
   └────────────────┴────────────────┘
        一个头可能学到"动词→主语"的依赖
        另一个头可能学到"动词→宾语"的依赖
        再一个头可能学到"介词→宾语"的依赖
```

一个注意力头只能在**一组权重**下做一次加权平均。如果句子同时需要"关注语法主语"和"关注语义相近词"，一个头会给出一个折中的、模糊的答案。

**多个头 = 多个不同的视角，各看各的，最后汇总。**

bang 的原文：

> Multi-Head：为捕获多种不同注意力，拆分后拼接。假设拆成 3 个 head，即捕获 3 种词间不同关系。

### 官方说法（论文）

> Multi-head attention allows the model to jointly attend to information from different representation subspaces at different positions.
>
> （多头注意力让模型能够**同时**关注来自**不同表示子空间**、**不同位置**的信息。）

"不同表示子空间"是关键词 —— 每个头有一组独立的 $W^Q_i, W^K_i, W^V_i$，相当于把输入投影到不同的"坐标系"里，在各自的坐标系里算注意力。

---

## 6.2 维度怎么切

论文的配置：

```
d_model = 512      模型维度
h = 8              头数
d_k = d_v = 512/8 = 64    每个头的维度
```

```
                    d_model = 512
        ┌──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┐
        │head 0│head 1│head 2│head 3│head 4│head 5│head 6│head 7│
        │ 64维 │ 64维 │ 64维 │ 64维 │ 64维 │ 64维 │ 64维 │ 64维 │
        └──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┘
               512 维被平均分成 8 份
```

**每个头都是完整的 Self-Attention，只是维度从 512 降到 64。**

### 一个必须澄清的点

"切分"这个说法容易引起误解，实际做法是：

**不是把 $X$ 的 512 维切成 8 段分别喂给 8 个头。**

而是**每个头都看到完整的 $X$（512 维），但各自用一个 $512 \times 64$ 的矩阵把自己投影到 64 维**：

```
         X (n, 512)  ← 完整的输入，8 个头都看它
              │
    ┌─────────┼─────────┬───── ... ─────┐
    ▼         ▼         ▼               ▼
  W^Q_0     W^Q_1     W^Q_2    ...    W^Q_7      （各是 512×64）
    ▼         ▼         ▼               ▼
  Q_0       Q_1       Q_2     ...     Q_7         （各是 n×64）
    ↓         ↓         ↓               ↓
  head0     head1     head2   ...    head7        （各算出 n×64 的输出）
    │         │         │               │
    └─────────┴─────────┴───── ... ─────┘
              Concat → (n, 512)
                 ↓
              W^O (512×512)
                 ↓
              (n, 512)
```

**注意**：每个头看到的都是**完整的 512 维输入**，只是通过不同的矩阵"压"到 64 维。说"把 512 维切成 8 份"是一种便于理解的简化说法。

### 参数量对比

这部分很有意思 —— **多头几乎不增加参数量**。

| 方案 | 单个头的 $W^Q$ 形状 | $W^Q$ 总参数 |
|---|---|---|
| **单头，全维度** | $512 \times 512$ | $262{,}144$ |
| **8 头，每头 64 维** | $512 \times 64$，共 8 个 | $8 \times 32{,}768 = 262{,}144$ |

**完全一样！** 用公式表示：

$$d_{model} \times d_k \times h = d_{model} \times \frac{d_{model}}{h} \times h = d_{model}^2$$

所以：

$$\text{MHA 参数} = \underbrace{4d_{model}^2}_{W^Q, W^K, W^V, W^O} = 4 \times 512^2 = 1{,}048{,}576 \approx 1.05\text{M}$$

**多头是"免费的"** —— 同样的参数量，换来了 8 个不同视角的表达能力。这是 Transformer 设计里非常漂亮的一笔。

> 那代价是什么？**计算量**。8 个头要算 8 个 $n\times n$ 的注意力矩阵（每个头是 $O(n^2 d_k)$，8 个加起来 $O(8 n^2 \cdot 64) = O(n^2 \cdot 512)$，和单头 512 维一样）。
> 所以计算量也没增加。真正的代价是**实现上的并行度**和**显存**（要存 $h$ 个注意力矩阵用于反向传播）。

## 6.3 完整计算流程

### 公式

$$\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, \dots, \text{head}_h) W^O$$

$$\text{where } \text{head}_i = \text{Attention}(QW_i^Q,\ KW_i^K,\ VW_i^V)$$

### 分步（带形状）

设定：$n = 5$（序列长度），$d_{model} = 9$，$h = 3$，$d_k = d_v = 3$。

```
┌────────────────────────────────────────────────────────────────┐
│ 步骤 1：线性投影（每个头各有一套 W）                              │
├────────────────────────────────────────────────────────────────┤
│   Q_i = X @ W^Q_i :  (5,9) @ (9,3)  →  (5,3)      i = 0,1,2    │
│   K_i = X @ W^K_i :  (5,9) @ (9,3)  →  (5,3)                   │
│   V_i = X @ W^V_i :  (5,9) @ (9,3)  →  (5,3)                   │
├────────────────────────────────────────────────────────────────┤
│ 步骤 2：每个头独立做注意力                                       │
├────────────────────────────────────────────────────────────────┤
│   S_i = Q_i @ K_i^T :  (5,3) @ (3,5)  →  (5,5)                 │
│   A_i = softmax(S_i / sqrt(3))       →  (5,5)                  │
│   Z_i = A_i @ V_i     :  (5,5) @ (5,3) →  (5,3)                │
├────────────────────────────────────────────────────────────────┤
│ 步骤 3：拼接                                                     │
├────────────────────────────────────────────────────────────────┤
│   Concat(Z_0, Z_1, Z_2) :  3 个 (5,3)  →  (5,9)                │
├────────────────────────────────────────────────────────────────┤
│ 步骤 4：输出投影                                                 │
├────────────────────────────────────────────────────────────────┤
│   Output = Concat @ W^O :  (5,9) @ (9,9)  →  (5,9)             │
└────────────────────────────────────────────────────────────────┘
```

### 为什么最后还要一个 $W^O$

**拼接只是把三个头"并排放"，它们之间还是互不通信的。**

```
Concat 的结果：
    我 [  h0的三个数  │  h1的三个数  │  h2的三个数  ]
         └─ 一个头的结论 ─┘ └─ 另一个头的结论 ─┘
```

逐元素看，第 0 维只来自 head 0，第 3 维只来自 head 1，第 6 维只来自 head 2。

**$W^O$ 做一次线性变换，让不同头的输出真正混合起来**，形成最终的统一表示。

没有 $W^O$ 的话，8 个头就是 8 段互不相干的向量，后面层还得自己学怎么把它们揉在一起 —— 不如直接在这里揉好。

## 6.4 代码实现：一个关键技巧

**朴素实现**：写个 for 循环跑 8 次。

**实际实现**：一次矩阵乘法搞定，然后 reshape。

```python
class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, h, dropout=0.1):
        super().__init__()
        assert d_model % h == 0
        self.d_k = d_model // h      # 64
        self.h = h                   # 8
        # 用一个 (512, 512) 的 Linear 代替 8 个 (512, 64) 的 Linear
        self.linears = nn.ModuleList([nn.Linear(d_model, d_model) for _ in range(4)])
        self.dropout = nn.Dropout(p=dropout)

    def forward(self, query, key, value, mask=None):
        B = query.size(0)   # batch size

        # ---- 1. 一次性算出所有头的 Q/K/V，再"切开" ----
        # (B, L, 512) --Linear--> (B, L, 512)
        #            --view-->   (B, L, 8, 64)      ← 把 512 拆成 8×64
        #            --transpose(1,2)--> (B, 8, L, 64)  ← 把"头"提到前面
        query, key, value = [
            lin(x).view(B, -1, self.h, self.d_k).transpose(1, 2)
            for lin, x in zip(self.linears, (query, key, value))
        ]

        # ---- 2. 注意力：现在 B 和 h 都当成"批"维度，一次算完 8 个头 ----
        # (B, 8, L, 64) 的矩阵乘法，等价于 8 个 (B, L, 64) 的独立计算
        x, attn = attention(query, key, value, mask=mask)

        # ---- 3. 拼回去 ----
        # (B, 8, L, 64) --transpose--> (B, L, 8, 64) --view--> (B, L, 512)
        x = x.transpose(1, 2).contiguous().view(B, -1, self.h * self.d_k)

        # ---- 4. 输出投影 ----
        return self.linears[-1](x)
```

**这段代码有 3 个容易踩的坑**：

### 坑 1：`view` 和 `transpose` 的顺序

```python
# ❌ 错误
x.view(B, -1, self.h, self.d_k)
# 这是把 512 维按 [d_k, h] 的顺序切（64 一组，共 8 组），
# 而正确的是按 [h, d_k] 的顺序切（8 个 64 维的块）

# ✅ 正确
x.view(B, L, self.h, self.d_k)   # 512 = h * d_k，最后的维度按 (h, d_k) 排
```

因为 `nn.Linear(512, 512)` 的输出，第 $j$ 维对应的是 head $\lfloor j/64 \rfloor$ 的第 $j \bmod 64$ 维 —— **必须按这个顺序解读**，才能和"8 个独立的 512×64 矩阵"等价。

### 坑 2：`transpose` 之后必须 `contiguous`

`transpose` 只改变"怎么看"这个张量（改 stride），不复制数据。而 `view` 要求内存连续。

```python
x = x.transpose(1, 2).contiguous().view(B, -1, self.h * self.d_k)
#                     ^^^^^^^^^^^^ 少了这个会报错
```

或者直接用 `reshape`（它会自动处理这种情况）。

### 坑 3：mask 的维度

注意力分数是 `(B, h, T, L)`，四维。mask 需要能广播到这个形状：

```python
# mask 通常是 (B, 1, 1, L) 或 (B, 1, T, L)
# 广播规则：(B, 1, 1, L) ──广播──▶ (B, h, T, L) ✓
```

`unsqueeze` 的次数数错就会报 `The size of tensor a (5) must match the size of tensor b (10)` 这种错。

## 6.5 不同的头到底在学什么

这不是玄学，有人真的研究过。Clark 等人 2019 年的论文《What Does BERT Look At?》分析了 BERT 的注意力头，发现：

**1. 有些头专门看"语法关系"**

```
某个头学会了：动词 → 它的直接宾语
    吃了 → 苹果
    写了 → 信
    
另一个头学会了：介词 → 它的宾语
    在 → 桌子上
    从 → 北京
```

**2. 有些头专门看"位置相邻"**

```
某个头的注意力几乎只集中在相邻的词上（i → i+1）
这是在追踪局部顺序信息
```

**3. 有些头专门看"分隔符"**

```
注意力总是落在 [SEP] 或 [CLS] 上
这类头通常被认为是"无操作的"（no-op），因为不传递有用信息
```

**4. 还有一些头"什么也不干"**

研究发现可以**剪掉相当一部分头而不怎么掉性能**（约 20~40%），这催生了"头剪枝"的研究方向。

### 这意味着什么

**多头确实分化出了不同功能，但这种分化是训练自己涌现的，不是人设计的。**

我们只提供了"8 个独立的投影矩阵"这个结构，至于哪个头学什么，是梯度下降在这个结构下自己找出来的最优解。

## 6.6 三个常见误解

### 误解 1："多头是把句子分成几段，每个头处理一段"

❌ **完全错误。**

**每个头都能看到完整的序列。** head 0 也会处理"我"，head 7 也会处理"我"。区别只在于**它们用什么"眼光"去看**（不同的投影矩阵）。

```
✅ 正确理解：
   8 个头的差别是"视角"不同，不是"分工范围"不同。
   就像 8 个人看同一部电影，各自关注的点不一样，
   但每个人都要看完整部电影。
```

### 误解 2："多头是为了并行加速"

❌ **不是主要原因。** 多头本身就增加计算量（8 个 $n\times n$ 矩阵），不加速。

多头的目的是**表达力**（多个子空间）。当然，实现上利用矩阵乘法把 8 个头一次算完，确实比 for 循环快很多 —— 但这是实现技巧，不是设计动机。

### 误解 3："头越多越好"

❌ **不一定。**

| 头数 | 每头维度 | 问题 |
|---|---|---|
| 1 | 512 | 只有一个视角 |
| 8 | 64 | 论文的选择，效果好 |
| 16 | 32 | 每头太窄，表达能力受限 |
| 64 | 8 | 每头只有 8 维，注意力退化成噪声 |

**存在一个权衡**：头太多则每个头太窄（$d_k$ 太小，能表达的关系模式有限）；头太少则视角不够。

实际配置经验：$d_k$ 一般不低于 32。现代大模型的常见配置：

| 模型 | $d_{model}$ | $h$ | $d_k$ |
|---|---|---|---|
| 论文 base | 512 | 8 | 64 |
| GPT-3 | 12288 | 96 | 128 |
| LLaMA-7B | 4096 | 32 | 128 |
| Qwen-7B | 4096 | 32 | 128 |

**$d_k = 128$ 是个很常见的甜点值。**

> 现代改进：**GQA / MQA**（分组查询注意力）让多个 Query 头共享一组 K/V 头，
> 主要是为了减少推理时的 KV Cache 显存，不是为了表达力。见 [ch14](ch14-从Transformer到GPT.md)。

## 6.7 多头的另一种理解：子空间

用线性代数的视角看：

$$W_i^Q: \mathbb{R}^{512} \to \mathbb{R}^{64}$$

每个 $W_i^Q$ 把输入投影到一个**64 维的子空间**。

- $W_0^Q$ 可能把"是不是主语"的信息放大，把其他信息压掉
- $W_1^Q$ 可能把"和上一个词的距离"放大
- ……

然后在各自的子空间里算相似度。

**不同子空间 = 不同的"度量方式"。** 这就像判断两个人像不像：

- 按长相比 → 一组答案
- 按性格比 → 另一组答案
- 按专业背景比 → 又一组答案

多头就是**同时用多种度量方式衡量相似度**，最后综合。这比只用一种度量方式丰富的多。

## 6.8 本章小结

- **多头 = 多组独立的 $W^Q_i, W^K_i, W^V_i$，在多个子空间里并行做注意力。**
- $d_k = d_{model} / h$，论文是 $512/8 = 64$。
- **参数量不随头数增加**：$h \times (d_{model}\times d_k) = d_{model}^2$。
- 计算完拼接，**必须过一次 $W^O$** 让不同头的信息融合。
- 实现上用一次矩阵乘法 + `view`/`transpose` 完成，不是 for 循环。
- **每个头看的是完整序列**，区别在"视角"，不是"分工范围"。
- 不同的头确实会分化出不同功能（语法、位置、语义），但这是训练涌现的。
- 头数不是越多越好，$d_k$ 太小时表达力会退化。
