# 第 14 章 从 Transformer 到 GPT

> **本章目标**：理解"原始 Transformer"和"你现在用的 ChatGPT"之间是什么关系。
>
> 一句话答案：**GPT 就是原始 Transformer 的 Decoder 部分，去掉了交叉注意力，堆得更深、练得更大。**

---

## 14.1 三大流派

2017 年的原始 Transformer 是 Encoder-Decoder 结构，专为翻译设计。后来人们意识到，这两个部分可以拆开单独用，于是分化出三条路线：

```
                    原始 Transformer
                  （Encoder + Decoder）
                          │
        ┌─────────────────┼─────────────────┐
        ▼                 ▼                 ▼
   Encoder-only      Decoder-only      Enc-Dec（原版）
        │                 │                 │
     BERT (2018)      GPT (2018)        T5 (2019)
     RoBERTa           GPT-2/3/4         BART
     DeBERTa           LLaMA             mT5
                       Qwen
                       DeepSeek
```

| | Encoder-only | Decoder-only | Encoder-Decoder |
|---|---|---|---|
| 代表 | BERT | GPT 系列 | T5、BART |
| 注意力 | 双向（无掩码） | 单向（因果掩码） | 双向 + 单向 + 交叉 |
| 预训练任务 | MLM（完形填空） | 预测下一个词 | Span 去噪 |
| 擅长 | 理解（分类、抽取） | 生成 | 翻译、摘要 |
| 能否直接生成 | ❌ | ✅ | ✅ |

### 为什么 Decoder-only 最后赢了

**1. 一个模型干所有事**

```
BERT 路线：
    预训练 → 下游任务要加一个"任务头"，每个任务微调一份模型
    "情感分类"一个模型、"命名实体识别"一个模型……

GPT 路线：
    预训练 → 用自然语言描述任务就行了
    "把下面这句话翻译成英文：..."  → 直接输出答案
```

**生成能力是通用的** —— 分类可以写成"输出'正面'或'负面'"，抽取可以写成"输出其中的日期"。**所有任务都能转成"续写"。**

**2. 训练目标更"自然"**

| | 训练目标 | 监督信号密度 |
|---|---|---|
| MLM（BERT） | 遮住 15% 的词，猜这些词 | 只有 15% 的位置有监督 |
| **Next Token Prediction（GPT）** | **预测下一个词** | **100% 的位置都有监督** |

**每一个位置都是一个训练样本**，数据利用率高得多。同样一段文本，GPT 方式的监督信号是 BERT 的 6 倍以上。

**3. 更适合规模化**

Decoder-only 结构最简单（没有交叉注意力，没有 Encoder），参数量相同时**推理更省**，也更容易做各种工程优化（KV Cache、量化、并行）。

**4. 涌现能力**

规模大到一定程度后，Decoder-only 模型出现了**上下文学习（in-context learning）**：给几个例子就能学会新任务，不需要微调。这是 Encoder-only 路线做不到的。

> 这三条路线现在其实在**收敛**：T5 的 Encoder-Decoder 思路被证明在翻译等任务上仍有优势，
> 但主流大模型（GPT-4、Claude、LLaMA、Qwen、DeepSeek）全是 Decoder-only。

## 14.2 GPT 的确切结构

**GPT = 原始 Transformer 的 Decoder，做三处删改：**

```
原始 Decoder Block：                GPT Block：
┌──────────────────────┐           ┌──────────────────────┐
│ Masked Self-Attn     │           │ Masked Self-Attn     │   ✓ 保留
├──────────────────────┤           ├──────────────────────┤
│ Cross-Attention      │           │        ✗ 删掉         │   ← 没有 Encoder 了
│ (K,V 来自 Encoder)   │           │                      │
├──────────────────────┤           ├──────────────────────┤
│ FFN                  │           │ FFN                  │   ✓ 保留
└──────────────────────┘           └──────────────────────┘
```

**删掉交叉注意力之后，整个模型只剩一个"自回归语言模型"**：

```
输入： <bos> 今天 天气 真
输出：        今天 天气 真 好        ← 每个位置预测下一个词
```

**训练目标**：

$$\mathcal{L} = -\sum_{t=1}^{T} \log P(w_t \mid w_1, w_2, \dots, w_{t-1})$$

**就是"给定前面所有词，预测下一个词"** —— 唯一的目标，没有任何额外的任务设计。

### 这个目标为什么这么强

因为**要准确预测下一个词，模型必须理解很多东西**：

```
"今天天气真" → 下一个词可能是"好"/"热"/"冷"   （需要常识）

"鲁迅，原名周树人，浙江" → 下一个词是"绍兴"     （需要记住事实）

"3 + 5 =" → 下一个词是"8"                     （需要算术）

"他走进房间，发现___" → 需要推理和想象

"SELECT * FROM users WHERE id =" → 需要懂 SQL
```

**为了把下一个词预测准，模型被迫学会了语法、常识、事实、推理、编程……**

这就是"**预测下一个词**"这个简单目标能产生通用智能的原因 —— 它是压缩所有人类知识的"最通用任务"。

## 14.3 GPT-3 的规模

回顾 bang 文章里那组数据：

| 参数 | GPT-3 | 论文 base | 倍数 |
|---|---|---|---|
| $d_{model}$ | 12288 | 512 | 24× |
| $h$ | 96 | 8 | 12× |
| $d_k$ | 128 | 64 | 2× |
| $N$（层数） | 96 | 6 | 16× |
| 上下文长度 | 2048 | — | — |
| 参数量 | 1750 亿 | 6500 万 | 269× |
| FFN 中间维度 | 49152 | 2048 | 24× |

**架构几乎没变，只是把数字放大了。**

### FFN 参数占了多少

$$\text{每层 FFN 参数} = 2 \times d_{model} \times d_{ff} = 2 \times 12288 \times 49152 = 12.08\text{亿}$$

$$\text{全部 96 层} = 12.08\text{亿} \times 96 = 1160\text{亿}$$

而 GPT-3 总共 1750 亿参数 → **FFN 占了 66%**。

**你手机里那个"知识渊博"的 AI，2/3 的"脑容量"都花在了 FFN 上。** 这和 [ch08](ch08-前馈网络FFN.md) 讲的 key-value memory 视角是一致的：**知识主要存储在 FFN 里。**

## 14.4 注意力的平方复杂度问题

### 问题

$$\text{注意力计算量} = O(n^2 \cdot d)$$

```
n = 2048  →  注意力矩阵 2048 × 2048 = 420 万个格子
n = 8192  →  8192 × 8192 = 6700 万个格子       （长度 ×4，矩阵 ×16）
n = 128K  →  128K × 128K = 164 亿个格子        （长度 ×64，矩阵 ×4096）
```

**序列长度翻倍，注意力计算量和显存都翻 4 倍。**

### 为什么这很致命

```
多轮对话、长文档问答、代码仓库分析……
这些场景都需要很长的上下文

但：
  显存装不下那个 n×n 矩阵
  计算时间也无法接受
```

### 解决方向

| 方向 | 代表技术 | 思路 |
|---|---|---|
| **算法优化** | FlashAttention | 不显式存 $n\times n$ 矩阵，分块计算，IO 感知 |
| **稀疏化** | Longformer、BigBird | 只算局部的 + 少量全局的注意力 |
| **线性注意力** | Linear Attention | 用核函数近似，把 $O(n^2)$ 降成 $O(n)$ |
| **位置外推** | RoPE + NTK / YaRN | 让训练时短的模型能处理更长的序列 |
| **架构改动** | Mamba / SSM | 换掉注意力机制 |

**目前最成功的是 FlashAttention** —— 它不改变数学结果（还是精确注意力），只是优化了 GPU 显存访问，把速度提升几倍、显存降低数倍。**现在几乎所有大模型都用它。**

> **重要认知**：$O(n^2)$ 是 Transformer 的**结构性问题**，不是实现问题。
> 从 512 到 128K 上下文的进步，主要是**工程优化（FlashAttention）+ 位置编码外推（RoPE）**，而不是把复杂度降下来了。

## 14.5 KV Cache：推理加速的关键

[ch10](ch10-Decoder与掩码机制.md) 提过，这里展开。

### 问题

自回归生成时，第 $t$ 步要算 $t$ 个位置的注意力：

```
生成第 1 个词：算 1 个位置
生成第 2 个词：算 2 个位置
...
生成第 100 个词：算 100 个位置
总计：1+2+...+100 = 5050 次位置计算

但其中 4950 次是重复的！（前面位置的 K、V 根本没变）
```

### 解决

**缓存已经算过的 K 和 V。**

```python
# 没有 cache：每步都要重算所有位置的 K、V
for t in range(max_len):
    Q, K, V = project(all_tokens_so_far)    # 前面的位置白算一遍
    ...

# 有 cache：只算新位置的 K、V，追加到缓存
for t in range(max_len):
    q_t, k_t, v_t = project(new_token)      # 只算 1 个位置
    K_cache = cat([K_cache, k_t])           # 追加
    V_cache = cat([V_cache, v_t])
    ...
```

**效果**：每步计算量从 $O(n^2)$ 降到 $O(n)$。生成 100 个词的总量从 $O(n^3)$ 降到 $O(n^2)$。

**实测加速通常是几十倍。**

### 代价：显存

缓存的大小：

$$\text{KV Cache} = 2 \times n \times d_{model} \times N_{layers} \times \text{batch} \times \text{精度字节数}$$

举例（LLaMA-7B，$d=4096$，$N=32$，fp16）：

```
每个 token 的缓存 = 2 × 4096 × 32 × 2 bytes = 512 KB

上下文 2048：  512KB × 2048 = 1 GB
上下文 32K：   512KB × 32768 = 16 GB      ← 超过模型本身（13GB）
上下文 128K：  512KB × 131072 = 64 GB     ← 显存爆炸
```

**这就是"长上下文很贵"的直接原因** —— 不是权重装不下，而是 KV Cache 装不下。

### MQA 和 GQA

**减少 KV Cache 的主流方案**：让多个 Query 头**共享**同一组 K/V 头。

```
MHA（标准多头）：每个 Q 头有自己的 K、V 头
    Q0 Q1 Q2 Q3 Q4 Q5 Q6 Q7
    K0 K1 K2 K3 K4 K5 K6 K7      → 8 组 KV
    V0 V1 V2 V3 V4 V5 V6 V7

MQA（Multi-Query）：所有 Q 头共享 1 组 K、V
    Q0 Q1 Q2 Q3 Q4 Q5 Q6 Q7
    K0 K0 K0 K0 K0 K0 K0 K0      → 1 组 KV，缓存减少到 1/8
    V0 V0 V0 V0 V0 V0 V0 V0

GQA（Grouped-Query）：折中，每组 Q 头共享一组 K、V
    Q0 Q1 Q2 Q3 | Q4 Q5 Q6 Q7
    K0 K0 K0 K0 | K1 K1 K1 K1    → 2 组 KV，缓存减少到 1/4
    V0 V0 V0 V0 | V1 V1 V1 V1
```

**GQA 是现在的标准**（LLaMA-2/3、Qwen 都用），因为它在速度和效果之间取得了很好的平衡。

> 注意：MQA/GQA 只影响 K、V 的**数量**，Q 头还是每个都有。这是为了让"多种查询视角"保留下来（[ch06](ch06-Multi-Head-Attention.md) 的多头好处），同时省掉 K/V 的冗余。

## 14.6 现代 Transformer 的改进清单

从 2017 到 2025，架构有一些改进。**但没有一个是根本性的** —— 骨架仍然是"注意力 + FFN + 残差 + 归一化"。

| 组件 | 原始论文 | 现代主流 | 改了什么 |
|---|---|---|---|
| 归一化位置 | Post-LN | **Pre-LN** | 训练更稳，可省 warmup |
| 归一化方法 | LayerNorm | **RMSNorm** | 去掉均值中心化，只做缩放，更快 |
| 位置编码 | Sinusoidal | **RoPE** | 旋转 Q/K，天然相对位置，可外推 |
| 激活函数 | ReLU | **SwiGLU / GeGLU** | 门控，效果更好 |
| 注意力 | MHA | **GQA / MQA** | 省 KV Cache |
| 注意力实现 | 标准 | **FlashAttention** | IO 优化，快几倍 |
| Bias 项 | 有 | **大多去掉** | 省参数，效果不差 |
| 输出层 | Softmax | Softmax | 不变 |
| 词嵌入共享 | 共享 | **共享** | 标准做法 |

### RMSNorm 是什么

$$\text{RMSNorm}(x) = \gamma \odot \frac{x}{\sqrt{\frac{1}{d}\sum_i x_i^2 + \epsilon}}$$

**和 LayerNorm 的区别：不减均值，只除以均方根。**

```python
# LayerNorm：减去均值 + 除以标准差
x_norm = (x - x.mean()) / x.std()

# RMSNorm：不減均值，只除以 RMS
x_norm = x / sqrt((x ** 2).mean())
```

**为什么可以省掉均值？** 实验发现减均值对效果贡献很小，但计算要贵一些（要算两次统计量）。去掉之后更快，效果几乎不变。

### RoPE 是什么

**旋转位置编码**。回顾 [ch03 3.5 节](ch03-输入表示-词嵌入与位置编码.md) 的推导：

$$PE(pos+k) = R_k \cdot PE(pos) \quad \text{（旋转矩阵）}$$

RoPE 的思路：**既然相对位置可以用旋转表示，那就直接对 Q、K 向量做旋转。**

```
对位置 m 的 Q 向量和位置 n 的 K 向量，分别旋转 mθ 和 nθ：

    q_m' = R_{mθ} · q_m
    k_n' = R_{nθ} · k_n

则内积：
    q_m' · k_n' = q_m^T R_{mθ}^T R_{nθ} k_n = q_m^T R_{(n-m)θ} k_n
                            ↑
                    只和 (n - m) 有关！
```

**注意力分数天然只依赖相对距离**，不需要模型自己去学。

**RoPE 的好处**：

1. 相对位置直接内建
2. 可以通过调整 $\theta$ 的基数来**外推**到更长的序列（NTK-aware、YaRN 等技巧）
3. 没有任何额外参数

**几乎所有现代 LLM 都用 RoPE。**

### FlashAttention 是什么

**不改变数学结果**，只改变计算方式。

```
标准注意力：
    1. 算 S = QK^T，写进显存（n×n 的大矩阵）
    2. 读出来做 softmax
    3. 再写回去
    4. 读出来乘 V
    → 显存读写是瓶颈（GPU 计算很快，但显存带宽有限）

FlashAttention：
    把 Q、K、V 分块（tile），在 SRAM（极快的片上缓存）里
    一块块算，用 online softmax 技巧边算边归一化，从不显式
    生成完整的 n×n 矩阵
    → 显存访问大幅减少，速度快 2~4 倍，显存省数倍
```

**核心洞察：现代 GPU 的瓶颈是"数据搬运"，不是"计算"。** FlashAttention 是一个 IO 感知的算法，把搬运量降到最低。

## 14.7 涌现能力与上下文学习

这是规模带来的"意外惊喜"。

### 涌现（Emergence）

有些能力在小模型上**完全没有**，模型大到某个规模后**突然出现**：

```
模型规模        能力
─────────────────────────────────────
1 亿参数        能说通顺的短句
10 亿参数       能回答问题
100 亿参数      能做简单推理
1000 亿参数     能写代码、做数学、多步推理、上下文学习
```

**这些能力不是"慢慢变好"，而是"突然出现"。** 这被称为涌现。

**为什么会有涌现？** 目前没有公认的解释。一种说法是：某些能力需要"多个子技能同时具备"才能表现出来，而子技能各自随规模平滑提升 —— 只有全部到位，能力才会显现。

### 上下文学习（In-Context Learning）

**这是 Decoder-only 大模型最神奇的能力。**

```
Prompt:
    把下面的词翻译成英文：
    苹果 → apple
    香蕉 → banana
    橘子 →

模型输出：orange

关键：模型从没被专门训练过这个任务，
      它只是"看着例子"就学会了！
```

**三种模式**：

| 模式 | 说明 |
|---|---|
| Zero-shot | "把'苹果'翻译成英文" |
| One-shot | 给一个例子 |
| Few-shot | 给几个例子 |

**这完全改变了 AI 的使用方式**：

```
BERT 时代：
    收集标注数据 → 微调模型 → 部署
    （每个任务都要一份数据 + 一次训练）

GPT 时代：
    写好 prompt → 直接用
    （不需要训练，不需要标注数据）
```

**这就是 GPT-3 论文标题《Language Models are Few-Shot Learners》的含义。**

> 从"训练模型"到"提示模型"，这是 Transformer 带给 AI 领域最深远的变化之一。

## 14.9 回到 bang 的总结

bang 在文章结尾的这段总结，放到今天看依然准确：

> 该架构能衍生出智能并扩展到多模态（语音、图像、视频效果都很好），核心有两点：
> - **上下文信息充足**
> - **并行计算能力强**
>
> 我认为其他算法架构若能充分融入上下文信息，规模大了也能有智能，只是 **Transformer 可并行运算的特性让当前计算机算力触及涌现的临界点**。

**这段话有三层洞察**：

**1. "上下文信息充足"是智能的必要条件**

每个 token 都能直接访问全序列 —— 这让模型能建立任意复杂的关联。

**2. "并行计算能力"是规模化的前提**

不能并行 → 无法用几千张卡训练 → 规模上不去 → 触不到涌现的临界点。

**3. "触到临界点"才是关键**

智能可能不是 Transformer 独有的。但 Transformer 是**第一个能被推到足够规模**的架构。

**换句话说：不是 Transformer 必然通向智能，而是智能的临界点恰好在这个架构的可达范围内。**

## 14.10 本章小结

- 三大流派：**Encoder-only（BERT）、Decoder-only（GPT）、Enc-Dec（T5）**。
- **Decoder-only 胜出**：统一生成范式、监督信号密度高、结构简单易规模化、支持上下文学习。
- **GPT = 原始 Decoder 去掉交叉注意力**，只保留带因果掩码的自注意力和 FFN。
- 训练目标只有一个：**预测下一个词**。为了预测准，模型被迫学会语法、事实、推理。
- **GPT-3 的 FFN 占 66% 参数** —— 知识主要存在 FFN 里。
- 注意力是 $O(n^2)$，这是长上下文昂贵的根本原因；FlashAttention 优化 IO 但不改复杂度。
- **KV Cache** 把推理每步从 $O(n^2)$ 降到 $O(n)$，代价是显存；**GQA/MQA** 用来省这份显存。
- 现代改进：**Pre-LN、RMSNorm、RoPE、SwiGLU、GQA、FlashAttention** —— 骨架没变，局部优化。
- **涌现和上下文学习**是规模带来的质变，改变了 AI 的使用范式。
