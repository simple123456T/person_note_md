# 第 1 章 为什么需要 Transformer

> **本章目标**：搞清楚 Transformer 想解决什么问题，以及它凭什么取代了 RNN。
> 这一章不涉及任何公式，只要建立"动机"，后面所有设计你都能理解成"为了解决问题而做的选择"。

---

## 1.1 先明确：我们要解决什么问题

Transformer 诞生于**机器翻译**任务：给一句中文，输出对应的英文。

```
输入：我 有 一 只 猫
输出：I  have  a  cat
```

这类问题的共同特点是：

1. **输入是一个序列**，长度不固定（3 个词、30 个词都可能）。
2. **输出也是一个序列**，长度和输入不一定相等。
3. **词与词之间有依赖关系**，而且可能隔得很远。

第 3 点是最麻烦的。看这个例子：

```
The animal didn't cross the street because it was too tired.
                                           ↑
                               这个 "it" 指的是什么？
```

要正确理解 `it`，模型必须回头看 5 个词之前的 `animal`。
如果句子再长一点：

```
The animal that I saw in the zoo last weekend with my daughter didn't cross the street because it was too tired.
                                                                                               ↑
                                                                                        还是指 animal
```

`it` 和 `animal` 中间隔了 15 个词。**模型能不能"记住"这么远的信息，直接决定了它行不行。**

这种「当前位置需要参考序列中其他位置」的能力，专业叫法是**长距离依赖（long-range dependency）**。

---



## 1.2 老方案一：RNN / LSTM —— 排队一个个处理

在 Transformer 之前，主力是 RNN（循环神经网络）和它的改进版 LSTM、GRU。

### 它是怎么工作的

RNN 的思路非常直觉：**像人读句子一样，从左到右一个词一个词地读，边读边记。**

```
        ┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐
        │ h_1 │───▶│ h_2 │───▶│ h_3 │───▶│ h_4 │
        └─────┘    └─────┘    └─────┘    └─────┘
输入:     我         有        一只        猫
```

数学上就是：

$$h_t = f(h_{t-1}, x_t)$$

第 $t$ 步的隐藏状态 $h_t$，由「上一步的隐藏状态 $h_{t-1}$」和「当前输入 $x_t$」共同决定。

$h_t$ 就是这个"记忆"。理论上，只要 $h_t$ 足够大，它能记住前面所有信息。

### 问题 1：必须串行，无法并行

这是致命的。

要算 $h_4$，必须先算完 $h_3$；要算 $h_3$，必须先算完 $h_2$……**第 100 个词必须等前 99 个词全部算完。**

这意味着：

- 在 GPU 上，你有几千个计算核心，但这里只能用上 1 个 —— 其余全在空转。
- 句子越长，耗时线性增长，而且**无法通过加机器解决**。

训练一个 GPT 级别的模型，如果按 RNN 的方式，需要的时间是人类无法接受的。

### 问题 2：长距离信息会衰减

即使 LSTM 设计了"门控"机制来缓解，$h_t$ 这个固定大小的向量，要携带整句话的信息，仍然会：

- **信息瓶颈**：$h_t$ 通常只有几百到几千维，句子有 1000 个词时，前面词的信息被反复压缩、覆盖。
- **梯度消失**：反向传播时，梯度要沿着 $h_{100} \to h_{99} \to \dots \to h_1$ 一条链传回去，每传一步就乘一次小于 1 的数，传 100 步后梯度几乎变成 0。**前面的词学不到东西。**

一句话总结 RNN 的困境：**信息要走 $n$ 步才能从第 1 个词传到第 $n$ 个词，路太长了。**

---



## 1.3 老方案二：CNN 做序列 —— 扩大感受野

另一种思路是用一维卷积（CNN），比如 Facebook 的 ConvS2S、Google 的 ByteNet。

```
卷积核大小 3，一层能看 3 个词：
     我   有   一只   猫
     └─┬─┘
      [卷积]  ← 第 1 层，每个位置能看到左右各 1 个词
```

卷积可以**并行**（每个位置同时算），比 RNN 快。但有个新问题：

- **感受野是局部的**。一层卷积只能看到相邻几个词。
- 要看到相距 100 个词的两个位置，需要**堆很多层**：卷积核为 $k$，堆 $L$ 层才能看到距离 $k^L$ 的信息……不对，是每层扩大 $k-1$，要覆盖距离 $n$ 需要大约 $n/(k-1)$ 层。

距离越远，需要的层数越多，路径越长，同样有 RNN 那种"信息要长途跋涉"的问题。

---



## 1.4 Attention 的登场

2014–2015 年，Bahdanau 等人在做 seq2seq 翻译时提出了一个关键改进：**Attention（注意力）**。

### 它想解决什么

原本的 seq2seq 是：Encoder 把整句话压缩成一个固定向量 $c$，Decoder 基于这个 $c$ 生成译文。

```
Encoder:  我 有 一只 猫  ──压缩──▶  [c]  ──▶ Decoder: I have a cat
                                    ↑
                          整句话就压成这一个向量，瓶颈！
```

Attention 的想法非常朴素：**翻译每个词的时候，不要只看那个压缩向量，而是回头把原文所有词都看一遍，看哪个词最相关就多看它几眼。**

```
翻译 "cat" 时：
    我     有    一只    猫
   0.05   0.05   0.15   0.75     ← 注意力权重，猫的权重最高
                        ↑
                    所以 "cat" 主要参考"猫"，也带一点"一只"的信息
```

于是 Δ「路径长度」从 $n$ 变成了 **1**：任意两个位置之间都直接相连，不用排队传递。

这是革命性的思路转变：**从「按顺序传递信息」变成「直接两两交互」。**

### 但 Attention 还是没摆脱 RNN

最初的 Attention 是**挂在 RNN 上的**：

```python
for t in range(len(sentence)):        # 还是得串行循环
    h_t = rnn(h_{t-1}, x_t)
    context = attention(h_t, encoder_states)
    output = decoder(h_t, context)
```

循环还在，并行问题还在，长距离梯度消失问题还在。

---



## 1.5 Attention Is All You Need：干脆把 RNN 删掉

2017 年，Google 的 8 位作者发表《Attention Is All You Need》，提出了一个大胆到近乎"离经叛道"的想法：

> **既然 Attention 这么好用，那 RNN 和 CNN 是不是根本不需要？**

于是 Transformer 诞生了 —— 一个**完全由 Attention 和前馈网络堆叠**构成的模型：

- ❌ 没有循环结构（no recurrence）
- ❌ 没有卷积（no convolution）
- ✅ 只有 Attention + 全连接层 + 残差 + LayerNorm

结果：在 WMT 2014 英德翻译任务上，BLEU 达到 28.4，**比当时最好的模型高 2 个 BLEU 以上，而且训练成本降低了一个数量级。**

BLEU 高 2 分是什么概念？在这个任务上，通常改进 0.5 分就算显著进展。

### 训练成本的对比

论文里给了一个很直观的数据：base 模型用 **8 块 P100 训练 12 小时**，big 模型训练 3.5 天。
而当时同等效果的 RNN 模型，训练周期通常以**周**为单位。

---



## 1.6 Transformer 的两个核心优势

bang 在他那篇文章的结尾总结得很到位，Transformer 的成功可以归结为两条：

### 优势一：上下文信息充足 —— 任意两词距离都是 1

在 Self-Attention 里，序列中**任意两个位置**都要算一次注意力。

```
RNN:        我 → 有 → 一只 → 猫          猫要拿到"我"的信息，走 3 步
            (信息沿链传递)

Self-Attn:  我 ─┬─ 有 ─┬─ 一只 ─┬─ 猫     所有词两两相连，1 步直达
              └───────┴────────┘
```

- **路径更短**，长距离依赖不再靠"记忆接力"，而是"直接查表"。
- **梯度不用走长链**，前面的词也能得到充分的梯度信号。

一句话：**每个位置的表示，都是全句所有位置信息的一次加权融合。**

### 优势二：并行计算 —— 这是真正的杀手锏

还是对比：

```
RNN 计算 h_5 的依赖：
    h_1 → h_2 → h_3 → h_4 → h_5
    ↑ 必须等前面全算完

Self-Attention 计算位置 5 的依赖：
    X (整个矩阵)  ──矩阵乘法──▶  Z
    ↑ 所有位置同时算，一次矩阵乘法搞定
```

Self-Attention 的整个运算就是几个矩阵乘法：

$$Z = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

矩阵乘法天然适合 GPU —— GPU 上有成千上万个核心，就是为大规模矩阵乘法设计的。

**这意味着什么？** 意味着你可以把模型做到百亿、千亿参数，可以用几万张卡一起训练。而 RNN 做不到 —— 无论加多少卡，都只能一个一个词地算。

bang 的原文观点值得引用：

> 该架构能衍生出智能并扩展到多模态，核心有两点：**上下文信息充足**、**并行计算能力强**。其他算法架构若能充分融入上下文信息，规模大了也能有智能，只是 Transformer 可并行运算的特性让当前计算机算力触及涌现的临界点。

也就是说：**并行能力 = 能堆规模 = 能撞上"涌现"的临界点**。这是 Transformer 最深远的影响。

## 1.7 一个具体的例子：为什么需要"两两交互"

用中英翻译来说明 Self-Attention 为什么有效：

```
中文：我 把 书 给 了 他
英文：I  gave  the  book  to  him
```

注意语序变了：中文是「给 了 他」，英文是「to him」在最后。

在 Self-Attention 里，处理英文的 `gave` 时，它可以：


| 关注对象     | 学到的权重（示意） | 作用                    |
| -------- | --------- | --------------------- |
| I        | 高         | 确定主语                  |
| 书 / book | 高         | 确定宾语                  |
| 给        | 高         | 确定谓语                  |
| 他 / him  | 中         | 确定间接宾语                |
| 了        | 低         | 时态信息，但英文靠 gave 的过去式表达 |


每个英文词都能**直接**去看任意一个中文词，不需要"从前往后一路传过来"。

## 1.8 Transformer 的影响：不止于 NLP

这才是它被称为"基石"的原因：


| 领域    | 代表模型                           | 说明                        |
| ----- | ------------------------------ | ------------------------- |
| 文本    | BERT (2018)、GPT 系列             | 预训练 + 微调 / 提示，NLP 全面转向    |
| 视觉    | ViT (2020)                     | 把图片切成 16×16 的 patch 当成"词" |
| 语音    | Whisper                        | 语音识别、翻译                   |
| 图像生成  | DiT、Stable Diffusion 的 UNet 部分 | 扩散模型的主干                   |
| 视频生成  | Sora                           | 时空 patch                  |
| 蛋白质结构 | AlphaFold 2                    | Evoformer 模块基于 Attention  |
| 多模态   | CLIP、GPT-4V                    | 把不同模态映射到同一空间              |


**一个 2017 年为翻译设计的架构，成了整个 AI 领域的通用计算范式。**

## 1.9 本章小结


| 方案                 | 并行能力   | 任意两词路径        | 主要问题                 |
| ------------------ | ------ | ------------- | -------------------- |
| RNN / LSTM         | ❌ 必须串行 | $O(n)$        | 慢、长距离信息衰减            |
| CNN                | ✅ 可并行  | $O(\log_k n)$ | 感受野局部，需要堆很多层         |
| **Self-Attention** | ✅ 可并行  | **$O(1)$**    | 计算量 $O(n^2)$（这是它的代价） |


Transformer 的核心洞察：

1. 序列建模的本质需求是**任意两个位置之间的信息交互**；
2. 这种交互可以**不依赖顺序的循环**来实现，用矩阵乘法一次算完；
3. 因此可以**极致并行**，从而把模型规模推向过去无法想象的程度。

> ⚠️ 注意最后一列的 $O(n^2)$：这是 Transformer 唯一的明显短板 —— 序列长度翻倍，注意力计算量翻 4 倍。这就是为什么上下文长度从 512 涨到 128K 花了这么多年（靠 FlashAttention、稀疏注意力、RoPE 外推等一系列工程和算法创新）。详见 [ch14](ch14-从Transformer到GPT.md)。
