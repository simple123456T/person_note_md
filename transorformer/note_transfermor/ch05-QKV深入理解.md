# 第 5 章 QKV 深入理解

> **本章目标**：用 bang's blog《Transformer 里的 Q K V 是什么》的讲法，把 Q、K、V 彻底钉死。
> 这一章不引入新概念，只做一件事：**把第 4 章的公式，用一套具体的数字从头到尾走一遍。**
>
> 所有数字都可以用 `code/bang_style_demo.py` 复现。

---

## 5.1 场景设定

bang 的文章用了这样一个例子：

```
输入：我 有 一 个 玩
任务：预测下一个字 → 期望是「具」（组成"玩具"）
```

我们把「个」换成「一」保持 5 个字，其他完全沿用：

```
token 序列： 我  有  一  个  玩     （5 个 token）
每个 token： 9 维向量              （bang 假设 9 维，GPT-3 实际是 12288 维）
输入矩阵 X： 5 行 9 列
```

**输入矩阵 X**（一行 = 一个 token）：

```
    我 [   0    0    1    1    0    1    1   -1    0 ]
    有 [   0    0    1    0   -1    0    1    0    0 ]
    一 [  -1    0    1   -1    0    0    1   -1    1 ]
    个 [   0    0    0    0    0    0    1    1    1 ]
    玩 [   1    0    0    1    0   -1    0   -1    0 ]
```

```
        d=9 列（每一列是一个特征维度）
      ┌─────────────────────────────────┐
 我   │  0   0   1   1   0   1   1  -1   0 │  ← 一个 token
 有   │  0   0   1   0  -1   0   1   0   0 │
 一   │ -1   0   1  -1   0   0   1  -1   1 │
 个   │  0   0   0   0   0   0   1   1   1 │
 玩   │  1   0   0   1   0  -1   0  -1   0 │
      └─────────────────────────────────┘
        n=5 行
```

> **再次强调这个约定：行 = token，列 = 特征。**
> bang 的原文是"5 个字、每字一个向量、每向量 9 维，排列成 5 行 9 列的输入矩阵 X，每行代表一个词"。

---

## 5.2 权重矩阵 W 的形状：为什么是 9×9

这是 bang 文章里讲得最清楚的一个点。

Self-Attention 需要三个权重矩阵 $W^Q$、$W^K$、$W^V$。它们的形状是 **9×9**。为什么？

### 行数 = 9：为了能乘上

$X$ 是 $5\times 9$，要用它去乘 $W$：

$$Q = X W^Q = (5 \times 9) \times (9 \times 9) = (5 \times 9)$$

**矩阵乘法要求"左矩阵的列数 = 右矩阵的行数"**，$X$ 的列数是 9，所以 $W$ 的行数必须是 9。

### 列数 = 9：为了进出一致

注意力模块的输入是 5×9，输出也必须是 5×9：

- 这样才能**多层堆叠**（第 1 层输出喂给第 2 层）
- 这样才能做**残差连接**（$X + \text{Attention}(X)$ 要求两者形状相同）

由矩阵乘法，输出列数 = 右矩阵的列数，所以 $W$ 的列数也是 9。

### 结论

$$W^Q, W^K, W^V \in \mathbb{R}^{9 \times 9} \quad\Longrightarrow\quad Q, K, V \in \mathbb{R}^{5 \times 9}$$

**一句话：$W$ 是方阵，是为了保证"进去多少维，出来还是多少维"。**

> 💡 **面试常问**：为什么 $W$ 不是 $9\times 3$ 之类的？
> 答：单头的情况下，为了保持输入输出维度一致以便堆叠，必须是 9×9。
> 多头的情况下，每个头的 $W$ 是 $9\times 3$（因为要把 9 维切成 3 个头，每头 3 维），
> 但拼接后还要再乘一个 9×9 的 $W^O$ 还原。见本章 5.7 节。

**这些 $W$ 里的数字就是模型要训练的参数。** bang 原文：

> Self Attention 包含 Wq、Wk、Wv 三个参数权重矩阵，**模型训练即不断调整其中的数值**。

## 5.3 把 X 投影成 Q、K、V

$$Q = XW^Q \qquad K = XW^K \qquad V = XW^V$$

用随机的 9×9 权重矩阵算出来（数值见 `code/bang_style_demo.py`）：

```
Q（5×9）—— "我要问什么"
    我 [   0    1    1   -1   -1   -1   -1    2   -1 ]
    有 [  -1    0    1    0   -1   -1    0    2   -1 ]
    一 [  -3    0    2   -1    1    2   -1    1   -2 ]
    个 [   0   -1    2    0   -2    1    1    1   -1 ]
    玩 [  -1    3   -1    1    0   -2   -1    0    0 ]

K（5×9）—— "我是什么，可以被谁匹配"
    我 [  -2    0    1    0   -1   -2    1    1    0 ]
    有 [   0    1    1    0    0   -1    0    0    0 ]
    一 [   0    2    1    2   -2   -1    1    2    3 ]
    个 [   2   -1   -1    1   -2   -1    0    0    2 ]
    玩 [   0   -2    3    0    0    1   -2    1    0 ]

V（5×9）—— "如果被关注，我提供什么内容"
    我 [   0   -1    1    0   -3   -2   -1    1   -1 ]
    有 [   0    0    1   -1   -2   -2    0    0    0 ]
    一 [   0   -3    2   -1   -4   -1   -2   -1    1 ]
    个 [   0    0    0    0   -1   -2    0    2   -1 ]
    玩 [  -1    0    1   -1   -1    0    0   -1   -1 ]
```

### 三个关键理解

**1. Q、K、V 的每一行仍然是一个 token**

不是"Q 是 5 个词、K 是另外 5 个词"，而是**同样的 5 个词，各自换了一套表示**。

```
"我" 这个词：
   在 X 里是 [0, 0, 1, 1, 0, 1, 1, -1, 0]      ← 原始词义
   在 Q 里是 [0, 1, 1, -1, -1, -1, -1, 2, -1]   ← 作为"提问者"的表示
   在 K 里是 [-2, 0, 1, 0, -1, -2, 1, 1, 0]     ← 作为"被检索项"的表示
   在 V 里是 [0, -1, 1, 0, -3, -2, -1, 1, -1]   ← 作为"内容提供者"的表示
```

**2. 每个 token 的投影是独立的**（bang 原文）

> 由矩阵乘法特性，第一行每个数据只由原矩阵第一行与 W 运算得来，与其他行无关。

数学上：$Q_{i,:} = X_{i,:} W^Q$，只用到 $X$ 的第 $i$ 行。
**到这一步为止，token 之间的信息还没有任何交互。**

**3. 那 token 之间什么时候开始交互？**

**下一步，$QK^T$ 的时候。**

## 5.4 算注意力分数：$S = QK^T$

$$S = QK^T = (5\times 9)\times(9\times 5) = (5\times 5)$$

```
S 原始分数（5×5）
    我 [    5.00     3.00     4.00    -2.00     4.00 ]
    有 [    8.00     2.00     5.00    -2.00     4.00 ]
    一 [    3.00     0.00    -9.00   -17.00    11.00 ]
    个 [    4.00     0.00     3.00     0.00     8.00 ]
    玩 [    4.00     4.00     8.00    -1.00    -9.00 ]
```

### 逐格解读

$S_{ij} = q_i \cdot k_j$，是第 $i$ 个词的 Query 和第 $j$ 个词的 Key 的**内积**。

```
S[0][1] = 5.00   →  "我"的Query 和 "有"的Key 的内积 = 5.00
S[2][3] = -17.00 →  "一"的Query 和 "个"的Key 的内积 = -17.00（负相关，很排斥）
S[4][0] = 4.00   →  "玩"的Query 和 "我"的Key 的内积 = 4.00
```

**整个矩阵就是"5 个词两两之间关系强度"的完整图谱**（bang 原文：*计算每个单词对其他单词的 Attention 系数，是两两可重复排列组合*）。

### 三条重要观察

**观察 1：这是 $n\times n$ 的方阵，不是 $n\times d$**

```
      我    有    一    个    玩
 我 [ 5.0   3.0   4.0  -2.0   4.0 ]
 有 [ 8.0   2.0   5.0  -2.0   4.0 ]
 一 [ 3.0   0.0  -9.0 -17.0  11.0 ]
 个 [ 4.0   0.0   3.0   0.0   8.0 ]
 玩 [ 4.0   4.0   8.0  -1.0  -9.0 ]
      └──── 每个词都要和每个词算一次 ────┘
```

**维度从 9 变成了 5。** 这是一个"把特征维度压缩成关系维度"的过程：原来每个词有 9 个特征，现在每对词有 1 个关系值。

**观察 2：对角线是自己和自己的关系**

$S_{ii} = q_i \cdot k_i$。注意这**不等于**"自己最重要" —— 因为 $q_i$ 和 $k_i$ 是不同的投影，内积可正可负可大可小。看例子：

```
S 的对角线：5.0, 2.0, -9.0, 0.0, -9.0

"一"和"一"的关系是 -9.0（负的！）
```

这就回答了很多人第一个疑惑：**为什么自己关注自己的权重不一定最高？** 因为 Q 和 K 是两个不同的投影，"我提问的内容"和"我作为被检索项的特征"未必匹配。

**观察 3：$S$ 不是对称的**

```
S[0][1] = 3.0   但   S[1][0] = 8.0
```

"我关注有"和"有关注我"是**两个不同的强度**。这完全合理：在语言里，"形容词"关注"名词"的方式和"名词"关注"形容词"的方式本来就不同。

> 这也解释了为什么必须有**两个**矩阵 $W^Q$ 和 $W^K$，而不能共用一个。

## 5.5 缩放与 softmax

### 先除以 $\sqrt{d_k}$

这里 $d_k = 9$，$\sqrt{9} = 3$：

```
S / 3（缩放后）
    我 [  2.8868   1.7321   2.3094  -1.1547   2.3094 ]
    有 [  4.6188   1.1547   2.8868  -1.1547   2.3094 ]
    一 [  1.7321   0.0000  -5.1962  -9.8150   6.3509 ]
    个 [  2.3094   0.0000   1.7321   0.0000   4.6188 ]
    玩 [  2.3094   2.3094   4.6188  -0.5774  -5.1962 ]
```

（原理见 [ch04 第 4.5 节](ch04-Self-Attention从直觉到公式.md)。）

### 按行 softmax

```
A（注意力权重，每行和为 1）
    我 [  0.4073   0.1283   0.2286   0.0072   0.2286 ]
    有 [  0.7630   0.0239   0.1350   0.0024   0.0758 ]
    一 [  0.0098   0.0017   0.0000   0.0000   0.9885 ]
    个 [  0.0845   0.0084   0.0475   0.0084   0.8512 ]
    玩 [  0.0825   0.0825   0.8304   0.0046   0.0000 ]
```

### 第 2 行解读（"有"看全句）

```
"有" 的注意力分布：我 76.3% | 有 2.4% | 一 13.5% | 个 0.24% | 玩 7.6%
```

**"有"把 76.3% 的注意力放在了"我"身上。**

> ⚠️ **重要提醒**：这里的权重是**随机初始化的**，还没有训练过，所以这些数字**没有语义含义**。
> 它只是演示"计算流程"。训练之后，模型才会学到"有"应该关注"我"这种真正的语法规律。
> 这个问题在 5.10 节详细回答。

### 第 3 行解读（"一"看全句）

```
"一" 的注意力分布：我 0.98% | 有 0.17% | 一 0.00002% | 个 0.000006% | 玩 98.85%
```

这一行极度集中 —— 因为 $S[2][4] = 11$ 是所有分数里最大的（"一"的 Query 和"玩"的 Key 强烈匹配），缩放后还有 6.35，softmax 之后直接吃掉 98.85% 的权重。

**这就是 softmax 的"放大差距"特性**：即使原始分数差距是 11 vs 3，softmax 后变成 98.85% vs 0.98%。

### 3 条关于 softmax 的实用结论

1. **每一行和为 1**，且每个值都 > 0 → 是合法的概率分布，可以做加权平均。
2. **softmax 会放大差距**，分数略高就能拿到大部分权重 → 这是"注意力聚焦"的来源。
3. **极端情况下会退化成 one-hot** → 这正是除以 $\sqrt{d_k}$ 要防止的。

## 5.6 用权重去取 Value

$$Z = AV = (5\times5)\times(5\times9) = (5\times9)$$

```
Z（5×9）—— 融合了上下文信息的每个 token 的新表示
    我 [ -0.2286  -1.0931   1.2215  -0.5856  -2.6287  -1.3141  -0.8645  -0.0357  -0.4144 ]
    有 [ -0.0758  -1.1679   1.1326  -0.2346  -2.9548  -1.7135  -1.0330   0.5570  -0.7061 ]
    一 [ -0.9885  -0.0098   1.0000  -0.9902  -1.0213  -0.0230  -0.0098  -0.9788  -0.9983 ]
    个 [ -0.8512  -0.2269   1.0391  -0.9071  -1.3199  -0.2501  -0.1795  -0.7973  -0.8967 ]
    玩 [ -0.0000  -2.5737   1.8258  -0.9129  -3.7386  -1.1695  -1.7433  -0.7388   0.7433 ]
```

**形状从 5×5 变回 5×9** —— 因为 $A$ 是 $(n,n)$，$V$ 是 $(n,d)$，乘完还是 $(n,d)$。

### 拆解最后一行（bang 文章单独拆解的那一步）

预测下一个字时，用的是**最后一个 token「玩」**的那一行。它的注意力权重是：

$$A[4] = [0.0825,\ 0.0825,\ 0.8304,\ 0.0046,\ 0.0000]$$

于是：

$$z_{\text{玩}} = 0.0825\,v_{\text{我}} + 0.0825\,v_{\text{有}} + 0.8304\,v_{\text{一}} + 0.0046\,v_{\text{个}} + 0.0000\,v_{\text{玩}}$$

**逐项展开**（每一行是 $0.0825 \times$ 对应的 $V$ 行）：

```
0.0825 × V[我] = [ 0.0000  -0.0825   0.0825   0.0000  -0.2474  -0.1650  -0.0825   0.0825  -0.0825 ]  ← 占比  8.2%
0.0825 × V[有] = [ 0.0000   0.0000   0.0825  -0.0825  -0.1650  -0.1650   0.0000   0.0000   0.0000 ]  ← 占比  8.2%
0.8304 × V[一] = [ 0.0000  -2.4912   1.6608  -0.8304  -3.3216  -0.8304  -1.6608  -0.8304   0.8304 ]  ← 占比 83.0%
0.0046 × V[个] = [ 0.0000   0.0000   0.0000   0.0000  -0.0046  -0.0092   0.0000   0.0092  -0.0046 ]  ← 占比  0.5%
0.0000 × V[玩] = [ 0.0000   0.0000   0.0000   0.0000   0.0000   0.0000   0.0000   0.0000   0.0000 ]  ← 占比  0.0%
────────────────────────────────────────────────────────────────────────────────────────────────
逐列相加得 z_玩 = [-0.0000, -2.5737, 1.8258, -0.9129, -3.7386, -1.1695, -1.7433, -0.7388, 0.7433]
```

**这就把"加权求和"四个字完全展开了。**

### 从这张表能读出的 4 件事

1. **权重决定信息流向**：「一」拿了 83% 的权重，所以 $z_{\text{玩}}$ 里有 83% 的信息来自「一」。
2. **权重为 0 就等于完全屏蔽**：$A[4][4] = 0$，所以「玩」自己的 Value **一点都没进到 $z_{\text{玩}}$ 里**。
   这看起来反常，但完全合法 —— 模型学出来的权重就是可以这样。
3. **所有词都在贡献，只是比例不同**：即使权重只有 0.5% 的「个」，也在最后的向量里留下了痕迹（比如第 5 个维度 -0.0046）。
4. **新表示是"混合体"**：$z_{\text{玩}}$ 既不是 $v_{\text{玩}}$，也不是 $v_{\text{一}}$，而是按照某种比例调配出来的**新向量**。

bang 的原文说得很准：

> 例如「我」与「一」的权重为 0.1，则「一」的向量对最终「我」的向量结果影响很小，**若为 0 则无影响**。

### 输出的含义

> **输出每行仍表示一个单词，但其向量已集合上下文中每个单词的注意力信息。**

用一句话概括整个 Self-Attention：

```
    Z 的第 i 行 = "第 i 个词在读过全句之后，对自己的重新描述"
```

## 5.7 多头：把 9 维拆成 3 个头

`d=9`，假设我们想用 3 个头（bang 的原文就假设拆成 3 个 head），则每个头 $d_k = 9/3 = 3$。

```
                    d = 9
        ┌───────────┬───────────┬───────────┐
        │  head 0   │  head 1   │  head 2   │
        │  3 维      │  3 维      │  3 维      │
        └───────────┴───────────┴───────────┘

每个头都有自己的 Wq/Wk/Wv，形状是 9×3
```

**3 个头 = 3 个独立的 Self-Attention，只是每个头的维度窄了。**

### 三个头算出来的注意力权重（各不相同！）

```
head 0 的注意力权重
    我 [  0.1839   0.0579   0.3275   0.3275   0.1032 ]
    有 [  0.2732   0.0271   0.2732   0.2732   0.1534 ]
    一 [  0.3632   0.1145   0.2039   0.2039   0.1145 ]
    个 [  0.8517   0.0267   0.0475   0.0475   0.0267 ]
    玩 [  0.0950   0.0299   0.1692   0.1692   0.5368 ]

head 1 的注意力权重
    我 [  0.0579   0.1032   0.3275   0.3275   0.1839 ]
    有 [  0.1839   0.3275   0.1032   0.3275   0.0579 ]
    一 [  0.3465   0.0193   0.6172   0.0061   0.0108 ]
    个 [  0.2916   0.5194   0.0163   0.1637   0.0091 ]
    玩 [  0.1812   0.5749   0.0057   0.1812   0.0571 ]

head 2 的注意力权重
    我 [  0.8081   0.1430   0.0451   0.0014   0.0025 ]
    有 [  0.5030   0.1585   0.2824   0.0280   0.0280 ]
    一 [  0.6615   0.1170   0.2085   0.0065   0.0065 ]
    个 [  0.1145   0.1145   0.2039   0.2039   0.3632 ]
    玩 [  0.2909   0.1633   0.2909   0.0917   0.1633 ]
```

**关键观察：三个头学到的"关注模式"完全不同。**

- head 0：「个」极度关注「我」（85%）
- head 1：「一」关注自己（61.7%），「个」关注「有」（51.9%）
- head 2：「我」关注自己（80.8%），「一」关注「我」（66.2%）

这就回答了**为什么需要多头**：

> 不同的头可以捕获**不同类型的词间关系**。一个头可能在看语法依赖（主谓关系），
> 另一个头可能在看语义相似度，还有一个可能在看位置邻近。
> 如果只有一个头，模型只能学到一种"关注方式"。

bang 原文：

> Multi-Head：为捕获多种不同注意力，拆分后拼接。假设拆成 3 个 head，即**捕获 3 种词间不同关系**。

### 拼接与输出投影

三个头的输出各是 5×3，水平拼起来：

```
Concat（5×9）—— 三个头拼回 9 维
    我 [   0.6095   -0.9195    0.7178  │  -0.2520    0.3728    1.6375  │  -1.9510    0.6637    0.9975 ]
    有 [   0.8466   -0.9393    0.8531  │   0.3224    0.6954    0.9646  │  -1.6615    0.3164    0.9720 ]
    一 [   1.2042   -1.0198    0.7961  │   0.0999   -0.9322    1.8639  │  -1.7785    0.5379    0.9935 ]
                                     └─ head0 ─┘        └─ head1 ─┘          └─ head2 ─┘
```

然后再乘一个 9×9 的 $W^O$（输出投影），把拼接结果**融合**起来：

```
Multi-Head Attention 最终输出
    我 [   0.9043   -1.0280    1.5394    2.0832   -1.1175   -3.2547    1.9510    0.9700    3.3365 ]
    有 [   1.5095   -0.1180    1.0227    1.1639   -0.0803   -1.9706    1.6615   -0.2971    2.9486 ]
    一 [   0.2983   -0.6597    1.1407    1.0859   -0.6618   -3.1868    1.7785    0.7442    3.7422 ]
    个 [   4.2556    2.2056    0.5012   -2.6917    0.3164   -0.7644    1.2289   -2.3273    2.5368 ]
    玩 [   0.2200   -0.0645    0.6108    2.0205    2.1178   -1.0327    1.4542   -0.4196    2.6410 ]
```

**形状 5×9，和输入完全一致。** ✓

> **$W^O$ 的作用**：拼接只是把三个头的输出"并排放在一起"，彼此之间还是孤立的。
> $W^O$ 做一次线性变换，让不同头的信息真正**混合**起来。

完整的多头公式：

$$\text{MultiHead}(Q,K,V) = \text{Concat}(\text{head}_1, \dots, \text{head}_h)W^O$$
$$\text{head}_i = \text{Attention}(QW_i^Q,\ KW_i^K,\ VW_i^V)$$

详见 [ch06 多头注意力](ch06-Multi-Head-Attention.md)。

## 5.8 掩码（Mask）

上面算出来的 $Z$，**每一行都包含了全句所有词的信息**。这在 Encoder 里没问题（本来就是双向的），但在 Decoder 里不行。

因为 Decoder 是**从左往右生成**的：生成第 3 个词时，第 4、5 个词还不存在，不能让模型"偷看"。

### 掩码矩阵

```
mask（1 = 遮住）
    我 [   0    1    1    1    1 ]
    有 [   0    0    1    1    1 ]
    一 [   0    0    0    1    1 ]
    个 [   0    0    0    0    1 ]
    玩 [   0    0    0    0    0 ]
```

**上三角全遮住**，意思是：第 $i$ 个位置只能看到 $0 \sim i$。

### 怎么遮：softmax 之前把分数设成 $-\infty$

```
被遮住的分数
    我 [  2.8868    -inf     -inf     -inf     -inf ]
    有 [  4.6188  1.1547     -inf     -inf     -inf ]
    一 [  1.7321  0.0000  -5.1962     -inf     -inf ]
    个 [  2.3094  0.0000   1.7321   0.0000     -inf ]
    玩 [  2.3094  2.3094   4.6188  -0.5774  -5.1962 ]
```

$e^{-\infty} = 0$，所以 softmax 之后这些位置就变成 0：

```
遮罩后的注意力权重
    我 [  1.0000   0.0000   0.0000   0.0000   0.0000 ]
    有 [  0.9696   0.0304   0.0000   0.0000   0.0000 ]
    一 [  0.8490   0.1502   0.0008   0.0000   0.0000 ]
    个 [  0.5682   0.0564   0.3190   0.0564   0.0000 ]
    玩 [  0.0825   0.0825   0.8304   0.0046   0.0000 ]
```

**每一行仍然和为 1**（bang 文章评论里有人质疑过这点，实际上只要用 softmax，行和必然为 1；如果实现里忘了按行归一化，或者用了 $-\infty$ 之外的填充方式且没重归一化，才会出现行和不为 1 的情况）。

**注意第 0 行变成了 `[1, 0, 0, 0, 0]`** —— "我"是第一个词，前面没有词，所以只能关注自己，权重 100%。

### 掩码的效果

```
带掩码的输出 Zm
    我 [  0.0000  -1.0000   1.0000   0.0000  -3.0000  -2.0000  -1.0000   1.0000  -1.0000 ]
    有 [  0.0000  -0.9696   1.0000  -0.0304  -2.9696  -2.0000  -0.9696   0.9696  -0.9696 ]
    一 [  0.0000  -0.8515   1.0008  -0.1510  -2.8506  -1.9992  -0.8506   0.8481  -0.8481 ]
    个 [  0.0000  -1.5251   1.2625  -0.3754  -3.1497  -1.6810  -1.2061   0.3621  -0.3056 ]
    玩 [ -0.0000  -2.5737   1.8258  -0.9129  -3.7386  -1.1695  -1.7433  -0.7388   0.7433 ]
```

**对照检查**：

- **第 0 行 `Zm[0]` 等于 `V[我]`** —— 因为权重是 `[1,0,0,0,0]`，只取自己的 Value。✓
- **第 1 行 `Zm[1]` = 0.9696×V[我] + 0.0304×V[有]** —— 只混了前两个词。✓
- **第 4 行 `Zm[4]` 和上面没加掩码的 `Z[4]` 一模一样** —— 因为最后一行本来就没有被遮的位置。✓

这就是 **Masked Self-Attention**。bang 原文的描述：

> 掩码后每个单词只含其所在位置之前的信息，例如第二行「有」只包含「我」和「有」，不含后面「一」「个」「玩」。

详见 [ch10 Decoder 与掩码机制](ch10-Decoder与掩码机制.md)。

## 5.9 用输出去预测下一个词

Decoder 的最后一层输出 $Z$ 之后，接一个线性层投影到词表大小，再 softmax：

```
z_玩（9 维）
    ↓ 乘以 W_out（9 × 词表大小）
logits（词表大小 维）
    ↓ softmax
每个候选词的概率
```

用一个玩具词表演示（权重随机，只为展示流程）：

```
z_玩 = [-0.0000  -2.5737   1.8258  -0.9129  -3.7386  -1.1695  -1.7433  -0.7388   0.7433]

logits = [ 0.9284  -0.4043  -2.0226   0.6018  -4.8462]

候选词概率：
    具  0.4901  ████████████████████████
    家  0.3535  █████████████████
    笑  0.1293  ██████
    球  0.0256  █
    吃  0.0015
```

（这里的候选词是随便选的，权重也是随机的，所以「具」概率最高纯属巧合 —— 训练之后才会真的有语义。）

**预测流程完整闭环**：

```
1. 输入「我 有 一 个 玩」
2. 经过 Embedding + 位置编码 + N 层 Transformer
3. 取最后一个位置（"玩"）的输出向量
4. Linear 投影到词表大小 + Softmax
5. argmax → 得到下一个词
6. 把预测出的词接到输入后面，回到第 1 步，继续生成
```

bang 原文：

> 每行包含前面所有单词的注意力信息，因此可用该表示预测下一个单词；**从矩阵最后一行「玩」的向量数值可预测对应下一个单词**。

## 5.10 Q、K、V 到底是什么（本质总结）

这是本章最重要的一节。bang 的定义值得完整引用：

> - **Q 可理解为原输入的词数据**，拿着这个数据去问："谁跟我有关系？"
> - **K 是被找的数据**，用于计算输入每个词之间的关系。
> - Q 和 K 用于算出 Attention 关系系数，知道每个 K 的数据跟 Q 是什么关系。
> - **K 和 V 同数据源**。由 Q 与 K 的运算知道每个 Q 与该数据源的关系系数，再与数据源运算，
>   就是把关系作用到源数据上，**使源数据做相应偏移**，也就是在 Q 作用下对源数据做相应推测。

### 用一句话概括三者

| | 一句话 | 类比 |
|---|---|---|
| **Q** | 我要找什么 | 你在搜索框里输入的关键词 |
| **K** | 我是什么（用于被匹配） | 每本书的标签/索引 |
| **V** | 我有什么（被取走的内容） | 每本书的实际内容 |

**Q 和 K 只负责"算关系"，V 负责"提供内容"。**

### 一个容易忽略的点：K 和 V 是同源的

在 Self-Attention 里，K 和 V 都来自同一个 $X$（只是乘了不同的矩阵 $W^K$、$W^V$）。
在 Cross-Attention 里，K 和 V 都来自同一个"被查询的序列"。

**为什么 K 和 V 要同源？**

因为逻辑上必须如此：

```
第 1 步：用 Q 和 K 算出"我和第 j 个位置有多相关" —— 这是**关于第 j 个位置**的判断
第 2 步：根据这个相关度，去取**第 j 个位置**的内容

如果 K 和 V 来自不同的源，第 2 步就变成了
"根据我和 A 的相关度，去取 B 的内容" —— 逻辑上说不通。
```

**K 是"标签"，V 是"内容"；标签指向哪本书，取的就是那本书的内容。**

### Self-Attention vs Cross-Attention

| 类型 | Q 来自 | K、V 来自 | 用途 |
|---|---|---|---|
| **Self-Attention** | $X$ | $X$（同一个 $X$） | Encoder 内部、Decoder 第一个注意力 |
| **Cross-Attention** | $X_{\text{decoder}}$ | $X_{\text{encoder}}$ | Decoder 第二个注意力 |

一句话：**Q、K、V 来自同一输入变换就是自注意力；来自不同输入就是交叉注意力。**

### ⚠️ 勘误：Stable Diffusion 里的交叉注意力

bang 的文章在讲交叉注意力时举了 Stable Diffusion 的例子：

> 文章举例称 Stable Diffusion 中 Unet 的交叉注意力模块里，**Q 是文字 prompt，K 和 V 是图片信息**。

**这个说法是反的。** 该文章评论区里也有读者（cong，2024-10-12）指出了这一点。

**实际情况**：在 Stable Diffusion 的 UNet 里，交叉注意力模块（`CrossAttention`）的：

```python
# Stable Diffusion UNet 中 CrossAttention 的实际实现（简化）
q = self.to_q(x)          # x = 图像特征（latent），所以 Q 来自图像
k = self.to_k(context)    # context = 文本 prompt 的 embedding，所以 K 来自文本
v = self.to_v(context)    # V 也来自文本
```

- **Q 来自图像**（UNet 当前的特征图，每个空间位置是一个 query）
- **K 和 V 来自文本 prompt**

**为什么这样设计？** 从"信息流"的角度想就通了：

```
图像特征（有空间结构，n = H×W 个位置）  →  发出 Query："我这个位置应该画什么？"
文本 prompt（n = 文本 token 数）        →  提供 Key/Value："这里有个词是'猫'"

结果：图像的每个位置都去文本里查询"我该画什么"，把文本信息融入图像特征。
```

所以那篇文章的读者 cong 说得对：**文字的编码应该作为 K、V，图像的编码作为 Q。**

> **注意**：bang 文章的其余部分（QKV 的运算、K 和 V 同源、掩码、多头）都是准确的，
> 只有这一处例子举反了。这里单独指出，避免学习时被误导。

## 5.11 回答一个评论区的好问题

bang 文章评论区有位读者（2024-11-21）提了一个非常关键的问题：

> "为什么随机定义的 Q、K 矩阵能逐渐学到上述目的？刚开始 Q 与 K 的乘积可能都是混乱的，
> 实际举例的参数都是学习好的参数，因此过程不清楚。"

### 回答

**对，随机初始化时确实是"混乱"的。** 看本章 5.5 节的注意力权重 —— 那些数字来自随机权重，你会发现它们**没有任何语义规律**（比如"一"关注"玩"98%，这在语言学上毫无道理）。

**关键在于：那些 $W^Q$、$W^K$、$W^V$ 矩阵是"可训练参数"，不是固定不变的。**

学习过程如下：

```
第 0 步：随机初始化 W^Q, W^K, W^V
         → 注意力权重是随机的（就像本章的数字）
         → 模型预测下一个词，猜得很差，损失很大

第 1 步：算损失对每一个参数的梯度
         梯度告诉每个参数："你往这个方向调一点点，损失会变小"

第 2 步：沿梯度方向更新参数
         W^Q ← W^Q - lr × ∂Loss/∂W^Q

第 3 步：用新的权重重新算一遍，损失小了一点点

重复几百万步：
         某些 W 的调整会让"动词更关注主语""形容词更关注名词"
         因为这些调整能降低预测下一个词的损失
```

**具体到一个例子**：

```
语料里有大量这样的句子：
    "猫 坐 在 垫子 上"  → 下一个词常常和"垫子"有关
    "狗 坐 在 地板 上"  → 下一个词常常和"地板"有关

如果模型能让"在"这个位置的表示更多地吸收"垫子/地板"的信息，
它预测后面词的准确率就会提高 → 损失下降
→ 梯度下降会自动地调整 W，让"在"对"垫子/地板"的注意力提高

"动词关注宾语"这种规律不需要人教，是从降低损失这个目标里"长"出来的。
```

**三个需要澄清的点**：

1. **本章的例子确实是"未训练"的。** 文章用它来演示**计算流程**，不是演示学习结果。这两件事要分开看。

2. **随机初始化也能工作**。梯度下降不需要一个好的起点，只需要一个"能算出梯度"的起点。而且随机性还能打破对称性（如果所有 $W$ 都初始化成一样的，所有头会学成一模一样的东西，那就浪费了多头）。

3. **多头正是在这个过程中分化出来的**。所有头一开始都是随机的、类似的，训练过程中因为初始化不同、梯度不同，逐渐分化成"关注语法"的头、"关注语义"的头、"关注位置"的头。这就是 5.7 节那张表里三个头模式不同的来源。

> **想亲手验证？** 运行 `code/train_toy_task.py`，你会看到模型从"完全随机"（loss ≈ 2.95，准确率 12.7%）
> 训练到"几乎全对"（准确率 93%+）的完整过程。

## 5.12 真实规模：GPT-3 有多夸张

bang 文章最后给了一组规模数据，值得记住：

| 参数 | GPT-3 | 论文 base 模型 | 倍数 |
|---|---|---|---|
| 词向量维度 $d_{model}$ | 12288 | 512 | 24× |
| 上下文长度（每层要算多少次注意力） | 2048 | — | — |
| 注意力头数 $h$ | 96 | 8 | 12× |
| 层数 $N$ | 96 | 6 | 16× |
| 参数量 | 1750 亿 | 6500 万 | 269× |

**注意上下文长度那一条**：

> 上下文长度 2048 —— 每个 token 都要与 2048 个 token 计算注意力。

也就是说，那个 $n \times n$ 的注意力矩阵是 **2048 × 2048 = 419 万个格子**，而且：

- 每个 head 要算一遍 → $\times 96$
- 每一层要算一遍 → $\times 96$

**只看注意力矩阵，GPT-3 处理一个 2048 长度的序列，就要算 $2048^2 \times 96 \times 96 \approx 386$ 亿个注意力分数。**

这就是 bang 说的"运算量巨大"。

这也解释了为什么大模型的推理成本那么高，以及为什么 **KV Cache**（[ch14](ch14-从Transformer到GPT.md)）这种优化如此重要。

## 5.13 本章小结

按数据流完整回顾：

```
1. 输入 X: 5×9（一行一个 token）
        ↓  X @ W^Q / W^K / W^V   （三个 9×9 的可学矩阵）
2. Q, K, V: 各 5×9（换了表示的同一批 token，此时 token 间还没交互）
        ↓  Q @ K.T
3. S: 5×5（两两关系矩阵，维度从 9 变成 5，这是唯一"混合"的地方）
        ↓  / sqrt(9)  → 分 softmax（每行）
4. A: 5×5（每行和为 1 的注意力分布）
        ↓  A @ V
5. Z: 5×9（融合了上下文的每个 token 的新表示）
        ↓  （多头：拆成 3 个头各自算，再 Concat 回 5×9，过 W^O）
6. 输出: 5×9，和输入形状完全一致 → 可以堆叠下一层
```

**核心要点**：

1. **$W$ 矩阵是方阵**，保证进出一致，方便堆叠和残差。
2. **Q、K、V 的每行仍是 token**，投影是逐 token 独立的，**交互发生在 $QK^T$**。
3. **$S$ 是 $n\times n$ 的非对称矩阵**，$S_{ij}$ 是 $i$ 对 $j$ 的关系强度；对角线是自我关系，**不一定最大**。
4. **softmax 按行做**，每行和为 1；它会**放大差距**，让注意力聚焦。
5. **$Z$ 的每一行 = 全句 Value 的加权平均**，权重为 0 就是完全屏蔽。
6. **多头 = 多个不同视角的注意力**，各自捕获不同的词间关系。
7. **掩码在 softmax 之前**，把未来位置设为 $-\infty$，效果是权重变 0 且每行仍和为 1。
8. **Q 提问，K 应答，V 交货**；K 和 V 必须同源。
