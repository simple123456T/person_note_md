## 全文记号约定

贯穿所有章节，看到这些符号就回想这张表：

| 符号 | 含义 | 论文里 base 模型的值 |
|---|---|---|
| $n$ / $L$ / $T$ | 序列长度（token 个数） | 不定 |
| $d$ / $d_{model}$ | 模型隐藏维度（每个 token 用多少维向量表示） | 512 |
| $h$ | 注意力头数 | 8 |
| $d_k$ | 每个头里 Q/K 的维度 $= d_{model}/h$ | 64 |
| $d_v$ | 每个头里 V 的维度（通常 $=d_k$） | 64 |
| $d_{ff}$ | FFN 中间层维度 | 2048 |
| $N$ | Encoder / Decoder 的层数 | 6 |
| $X$ | 输入矩阵，形状 $(n, d)$，**一行是一个 token** | — |
| $Q,K,V$ | Query / Key / Value 矩阵 | — |
| $C$ | Encoder 的输出编码矩阵 | — |

**最重要的一条约定：矩阵的一行 = 一个 token 的向量表示。**
记住这一点，几乎所有公式都能自己想出来。

## 一句话剧透

如果你只有 30 秒，这是 Transformer 的全部：

> 把每个词变成一个向量，用**三个不同的矩阵**把它投影成 Query、Key、Value；
> 用 Q 和 K 的内积算出「谁该关注谁」的权重，softmax 归一化后，
> 拿这个权重去**加权平均**所有人的 V，就得到了融合上下文的新表示。
> 把它和原输入相加、归一化，再过一个小 MLP，重复 N 层 —— 这就是 Transformer。

剩下的所有章节，都是在回答「为什么要这样设计」和「细节上怎么做才对」。
